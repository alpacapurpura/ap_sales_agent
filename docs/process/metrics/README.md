# Process Metrics

Captures token consumption, cache breakdown, tool usage, duration, and LOC delta per agent run (main session OR subagent invocation) extracted from Claude Code transcripts.

## Files

| File | Purpose | Lifecycle |
|---|---|---|
| `baseline-pre-R1-R9.jsonl` | Frozen snapshot 2026-04-29 → 2026-05-05 (pre-R1-R9 implementation). Reference baseline for ROI measurement. | Committed, immutable. |
| `runs.jsonl` | Rolling capture (R12 layer 1) of post-R1-R9 agent runs. Future. | Gitignored, append-only. |
| `report-{date}.md` | Aggregated reports (R12 layer 2). Future. | Committed when generated. |

## Provenance

Generated by `scripts/extract_baseline_metrics_from_transcripts.py` reading JSONL transcripts in `~/.claude/projects/-home-chris-AISALESHT/`.

Each row corresponds to either:
- **main session turn** — one assistant message in the orchestrator session
- **subagent invocation** — one `Agent` tool_result with `toolUseResult.agentType` set

{
  "ts": "ISO 8601",
  "session_id": "UUID of Claude Code session",
  "run_type": "main | subagent",
  "agent_type": "main | builder-backend | auditor-backend | architect-orchestrator | context-builder | gate-runner | general-purpose | Explore | ...",

  "total_tokens": 0,

  "tool_use_count": 0,
  "read_count": 0,
  "bash_count": 0,

Subagent-only fields (`total_tokens`, `duration_ms`, `tool_use_count`, `*_count`, `lines_*`) are absent or zero for `run_type = "main"` rows.

## Cost approximation

Tokens are NOT linearly priced. Apply per-component multipliers per Anthropic prompt-caching pricing:

| Component | Multiplier vs base input rate |
|---|---|
| `input_tokens` (uncached) | 1.0× |
| `cache_creation_5m_tokens` | 1.25× |
| `cache_creation_1h_tokens` | 2.0× |
| `cache_read_tokens` | 0.1× |
| `output_tokens` | ~5.0× (Opus 4.7: $0.015 / 1k vs $0.003 input) |

The `tokens_total` summary printed by the script is RAW SUM, intentionally lossy — use the per-component breakdown for cost analysis.

## Caveats

- Subagent runs that recursively spawn other subagents: the parent's `totalTokens` already includes children's tokens (Anthropic API rolls up). Do NOT double-count by summing parent + children.
- `model` field is `null` for subagent rows because Claude Code transcripts don't expose subagent's resolved model in `toolUseResult` (the agent definition's `model:` frontmatter is the source of truth — `haiku` for context-builder/gate-runner, `opus` for builder/auditor).
- Pre-2026-05-04 agent_types use legacy names (`nicolify-backend`, `nicolify-architect`, etc.). Post-migration uses SDD names (`builder-backend`, `architect-orchestrator`, etc.). Account for this when computing per-agent-type aggregates across the migration boundary.
