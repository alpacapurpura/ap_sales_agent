# Spec: data-storyteller Skill

> Date: 2026-03-29
> Status: Approved
> Type: Claude Code Skill

## Purpose

Skill for designing data visualizations that tell stories to non-technical small business owners. Complementary to `ux-disruptivo` (which handles general UI — forms, wizards, flows). `data-storyteller` owns any screen where **data is the protagonist**.

## Scope

- Any data-heavy screen in Nicolify (not just Growth Studio)
- Inline charts generated by Copilot (HTML output)
- Transversal to Bowtie stages when the need crosses boundaries

## Design Decisions

| Decision | Result |
|----------|--------|
| Relation to ux-disruptivo | Complementary (general UI vs data viz) |
| Scope | Any data-heavy screen + Copilot inline |
| Output | VIZ-SPEC.md (detailed spec with code examples when needed) |
| Metric knowledge | Light reference map + MCP/WebSearch + proposes better metrics |
| Chart libraries | Adaptive — audits installed libs, proposes if insufficient |
| Flow | Dual: Data-first or Question-first (detects or asks) |
| Bowtie awareness | Knows 8 stages as context, but prioritizes the actual need |
| Proposals | Text descriptions + HTML preview on demand |
| Name | `data-storyteller` |

## Role

Senior Data Visualization Designer specializing in marketing & sales analytics for small business owners. Thinks in stories, not charts. Every visualization answers a question.

**Core principle — The 5-Second Rule:** If the main insight isn't obvious within 5 seconds, the visualization is too complex.

## Mode Detection

| Signal | Mode | Flow |
|--------|------|------|
| "Tengo estos datos y no sé cómo mostrarlos" | Data-first | D1→D4→Spec |
| "Quiero ver cómo van mis anuncios" | Question-first | P1→P4→Spec |
| "Agrega un scorecard a esta pantalla" | Micro-change | Direct to Spec (delta) |
| "Genera un gráfico inline para Copilot" | Copilot-inline | Simplified → HTML |
| Unclear | Ask | "¿Vienes con datos o con una pregunta de negocio?" |

## Dual Flow

### Data-first

| Phase | Name | Purpose | Tools |
|-------|------|---------|-------|
| D1 | Understand data | What data exists, from where, what format. Audit backend | Glob, Grep, Read |
| D2 | Find the story | What story do these data tell? For whom? What decision? | Conversation |
| D3 | Design visualization | Chart type, layout, proposals (text + HTML on demand) | Read refs, MCP, WebSearch |
| D4 | Validate metrics | Are these the right metrics? Propose better ones | MCP, WebSearch |

### Question-first

| Phase | Name | Purpose | Tools |
|-------|------|---------|-------|
| P1 | Understand question | What business question? What decision follows? | Conversation |
| P2 | Map required data | What data answers this? Do we have it? Audit backend | Glob, Grep, Read |
| P3 | Design visualization | Same as D3 | Read refs, MCP, WebSearch |
| P4 | Validate completeness | Does the viz actually answer the original question? | MCP, WebSearch |

Both converge on **Final Phase: Spec** → writes `VIZ-SPEC-{feature}.md`.

**Critical gate per flow:**
- D2/P1 must produce a one-liner: *"This chart tells [persona] if [question], so they can [action]."*
- D4/P4 requires user confirmation that the proposal meets the need.

## Knowledge Routing

Three-step lookup when checking if a metric is obtainable:

1. **MCP first** (seconds): context7 for Meta/Google/GA4/YouTube, shopify-dev-mcp for Shopify
2. **WebSearch directed** (minutes): `site:developers.{platform}.com "{metric_name}"`
3. **Not found**: Declare explicitly, propose nearest alternative. Never invent.

Routing table lives in `references/metrics-map.md`.

## Reference Files

### metrics-map.md
- Platform → metric types → MCP or search pattern to find details
- Derived metrics with formulas (CAC, LTV, ROAS, Engagement Rate, etc.)
- Bowtie stage → primary/secondary KPIs mapping
- NOT exhaustive — a starting point for investigation

### chart-selection-guide.md
- Decision tree: "What do you want to show?" → chart type
- Universal rules (value+delta+trend, max 3 series, tooltips mandatory, no pie charts)
- Anti-patterns table (pie, 3D, dual Y-axis, gauge)
- Mobile rule: <768px collapses to scorecards only

### viz-spec-template.md
Template sections: Story, Data Sources, Metrics Displayed, Visualization Design (layout + chart specs + time handling), Progressive Disclosure (glance→explore→analyze→raw), Component Tree, States (loading/empty/error/partial), Color Mapping, Responsive Behavior.

## Design Rules (always apply)

- Max 5-7 KPIs per view
- Progressive disclosure: summary → chart → table → raw data
- Time always present: current value + delta% + trend direction
- Channel colors: Meta (#1877F2), Google (#EA4335), TikTok (#00F2EA), Organic (green), Email (amber)
- Never pie charts
- Labels in plain language + tooltip with technical definition
- Empty states with CTA to connect the data source
- Partial data: show what's available + "Datos parciales" badge

## HTML Preview (on demand)

When user asks to see a proposal:
1. Generate `/tmp/viz-preview-{timestamp}.html`
2. Use CDN of installed chart library (or Chart.js as universal fallback)
3. Representative mock data
4. Open in browser
5. Preview is disposable — concept validation only, not final code

## Integration

- **ux-disruptivo**: Complementary. Mixed screens (form + data): ux-disruptivo leads, data-storyteller consulted for data section only
- **nicolify-feature**: Can be invoked during UX phase for data-heavy features
- **frontend-expert**: Consumes VIZ-SPEC.md for implementation
- **nicolify-ux-designer agent**: For mechanical data screens (simple tables), the agent is faster
- **Copilot inline**: Output is direct HTML, not VIZ-SPEC
- **Bowtie**: Knows 8 stages as context, crosses them freely when the need is transversal

## Edge Cases

| Scenario | Handling |
|----------|---------|
| No data yet | Empty state with CTA to connect source |
| Partial data | Show available + "Datos parciales" badge |
| Metric not in API | Declare explicitly, propose alternative |
| Multiple sources for same metric | Define source priority in spec |
| Mixed screen (form + data) | ux-disruptivo leads, data-storyteller consulted |
| Real-time vs batch | Document update frequency per source |
| User requests wrong chart type | Explain why, propose alternative with justification |
