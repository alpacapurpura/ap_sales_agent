## 2. Class A — SQLAlchemy Table registration (DOMINANT)

### 2.1 Mechanism + symptom

Each AISALESHT model file declares `class X(Base): __tablename__ = "Y"`. Module
import side-effect = `Table("Y", Base.metadata, ...)` registers globally. Post-T-2-prep
(Pattern P6 prologue, commit `19230bc7`), Base singleton is unified — but the
collision still fires when BOTH AISALESHT model file AND luana-core equivalent
import simultaneously because both define `class TenantModel(Base)` registering
to the SAME `Base.metadata` namespace.

**Reproduction (verified live 2026-05-13 in this audit):**

```bash
cd /home/chris/AISALESHT/backend
.venv/bin/python -c "
from src.shared.domain.base_entity import Base
from src.modules.iam.infrastructure.models.tenant_model import TenantModel
from luana_core_iam.infrastructure.models.tenant_model import TenantModel as LTM
"
# → sqlalchemy.exc.InvalidRequestError: Table 'tenants' is already defined for this MetaData instance.
```

Order doesn't matter — error fires in both directions (AISALESHT first, then
luana fails; OR luana first, then AISALESHT fails). The root fix: AISALESHT
model file MUST be physically removed (or converted to re-export stub) so
only luana-core registers the table.

## 4. Class C — Module-level singletons (19 cases — all DELETE via codemod path rewrite)

### 4.1 Mechanism

`foo = ClassName(...)` at module top level instantiates a class at import
time. If both AISALESHT (`src.modules.X.module.foo`) and luana-core
(`luana_core_X.module.foo`) instantiate, two instances exist. Consumers
that import `from src.modules.X.module import foo` get the AISALESHT
instance; consumers using `from luana_core_X.module import foo` get the
luana instance. State divergence (e.g., `event_bus_adapter._handlers`
populated only in one tree) means handlers registered to AISALESHT-side
bus are invisible to luana-side consumers and vice-versa.

**After codemod runs** (T-2..T-7 rewrites every AISALESHT consumer to
`from luana_core_X.module import foo`), only the luana instance is
referenced. The AISALESHT instance is orphan — instantiated at import
but never read. Performance cost minimal (~0 lookups), but semantically
unused. Final cleanup is T-7 (delete `backend/src/shared/`) + T-14
(archive AISALESHT entirely) — at that point the AISALESHT singletons
disappear.
