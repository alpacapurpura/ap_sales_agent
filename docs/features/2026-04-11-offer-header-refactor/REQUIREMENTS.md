# Feature: Offer Studio Header + Lifecycle Refactor

**Date:** 2026-04-11
**Status:** Phase 1 — Requirements
**Source of truth UI:** `/tmp/ux-preview/offer-header-B-v4-1775915391.html`

---

## Summary

Refactorizar el editor de ofertas (`offer-studio`) para unificar navegación y lifecycle. Hoy existen dos layouts coexistentes (`OfferStudioLayout` main + `OfferEditorLayout` sidebar-rail) con rutas huérfanas, status read-only, "Vista Previa" placeholder, "Landing Page" ambiguo, "Guardar" manual sin feedback, y ningún control real del ciclo de vida de la oferta.

**Objetivo:** Un solo layout persistente con 4 tabs (Editor · Assets · Campañas · Conocimiento), lifecycle real Draft/Active/Paused/Archived controlado desde el header, landing con 4 estados contextuales, auto-save, y eliminación de componentes duplicados/mockeados.

## Affected modules

- **`offer`** (backend + frontend) — core refactor
- **`advertising`** (backend) — new read-only aggregation endpoint: `GET /offers/{id}/campaigns`
- **`sales_agent`** (backend integration) — `status` field debe ser leído por el agent para respetar Draft/Active/Paused semantics
- **`shared`** — posibles value objects nuevos (OfferLifecycle transitions)

## Lifecycle rules (MUST be enforced in service layer)

| From → To | Allowed? | Side effects |
|---|---|---|
| Draft → Active | ✅ (permissive, no gate) | Warn in modal if <90% (no landing). Sales Agent starts proposing. |
| Draft → Paused | ❌ (must go Active first, UI disables) | — |
| Active → Paused | ✅ | Sales Agent stops proposing but can reference historically. Landing **stays live** (parallel lifecycle). |
| Active → Draft | ✅ | Sales Agent stops. Landing stays live. Warn in modal. |
| Paused → Active | ✅ | Reactivates selling. |
| Paused → Draft | ✅ | — |
| Active/Paused → Archived | ✅ (kebab + modal) | Landing **auto-unpublishes**. Removed from "Mis ofertas", goes to "Archivadas". Reversible. |
| Archived → Active/Paused/Draft | ❌ (must restore first) | Via existing `POST /offers/{id}/restore` |

**Sales Agent semantics (documented for agentic integration):**
- `Draft` → Agent doesn't know about this offer. Filtered out of catalog.
- `Active` → Primary selling objective. Agent proposes proactively.
- `Paused` → Agent knows it existed. If client asks by name, acknowledges naturally without pushing. Not in proactive catalog. Doesn't negate existence.
- `Archived` → Filtered out completely, same as draft from agent's perspective.

## Landing page rules

1. **Generation requires offer completion ≥ 90%** (`health.completionPercentage` computed server-side — today it lives in frontend only, needs to move to domain/service).
2. **Generated landing has a snapshot version**: `offer_snapshot_version = hash(relevant_offer_fields)` or simply `offer.updated_at` at generation time.
3. **Outdated detection**: `is_outdated = landing.generated_at < offer.updated_at` when any field included in the snapshot has changed.
4. **Outdated display**: internal header badge (amber pulsing dot) + banner on public landing **visible only to owner** (not external visitors). Banner text: *"Tu oferta cambió desde que generaste esta landing. Regenerá para actualizarla."*
5. **Paused offer keeps landing live** (parallel lifecycle). Archived auto-unpublishes.
6. **"Edit in Puck" opens `/{tenantId}/editor/{offerId}`** (existing Puck route). From Puck the user can edit + publish manually.

## Auto-save rules

- Debounce: 800ms after last field change
- Indicator states: `idle` → `saving...` → `saved Ns ago` (passive)
- Error state: red inline banner with "Reintentar" button
- Sections already using `Sheet` pattern (`offer-edit-sheet-manager.tsx`) keep save-on-close behavior
- Full-form save button is REMOVED from header

## Tabs + URL pattern

- Use Next.js App Router **persistent layout**. `layout.tsx` at `/offer-studio/offer/[id]/` renders the shell (Row 1 + Row 2 + TabBar). Children pages:
  - `page.tsx` → Editor (default)
  - `assets/page.tsx` → Assets

- Each tab has a **real URL** → deep-linkeable from Copilot.
