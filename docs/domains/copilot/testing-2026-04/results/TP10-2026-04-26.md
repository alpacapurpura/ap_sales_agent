## Failures + root cause + fix aplicado

### B20-TP10 — F1 promise rota: `provider.routes()` no se consumía en `ROUTE_TOOL_MAP`

- **Síntoma:** Provider tp10_dummy declara `routes() → (ProviderRoute("*", ("tp10_dummy",)),)`. `discover_providers()` lo encuentra, `_build_tool_groups()` mergea su `tool_groups()` en `TOOL_GROUPS["tp10_dummy"] = [test_dummy_tool]`. Pero `get_tools_for_route("/copilot")` NO incluye `test_dummy_tool` porque `ROUTE_TOOL_MAP["*"]` es lista estática hardcoded en `tools/registry.py:150` y el group `"tp10_dummy"` no aparece. LLM nunca recibe el tool en bind_tools — S10.4 no podía pasar sin editar registry.py manualmente.
- **Trace evidence:**
  - Pre-fix: `'tp10_dummy' in TOOL_GROUPS = True`, `'tp10_dummy' in ROUTE_TOOL_MAP['*'] = False`, `test_dummy_tool` ausente en `[t.name for t in get_tools_for_route("/copilot")]`.
  - `grep "ProviderRoute\|p.routes()"` confirma único consumer de `provider.routes()` era `discovery.health()` para health check — no para route binding.
- **Root cause arquitectónico:** F1 implementó `_build_tool_groups` mergeando `tool_provider().tool_groups()` PERO dejó `ROUTE_TOOL_MAP` estático — `routes()` quedó wiring port sin consumer. Plug-and-play promise media: `tp.tool_groups()` mergeable + `provider.routes()` ignorada.
- **TDD fix aplicado:**
  - **(a) Test RED** en `tests/modules/copilot/test_route_tool_mapping.py::TestProviderRouteMerging` (3 tests):
    1. `test_provider_routes_extend_wildcard_fallback` — provider con `ProviderRoute("*", ("X",))` → `ROUTE_TOOL_MAP["*"]` incluye "X" + `get_tools_for_route("/anywhere")` retorna tools de X.
    2. `test_provider_routes_extend_specific_prefix` — provider con `ProviderRoute("growth-studio", ("X",))` → `ROUTE_TOOL_MAP["growth-studio"]` incluye "X", wildcard NO afectado, otras rutas NO ven X.
    3. `test_provider_routes_dedup_on_existing_group` — provider declarando group ya presente (e.g. "navigation") en prefix existente → no duplicate entry.
    Tests usan `monkeypatch.setattr(disc, "discover_providers", ...)` + `importlib.reload(reg)` para inyectar synthetic provider sin necesitar real module en disco (regression test independiente de tp10_dummy lifecycle).
  - **(b) GREEN fix** en `src/modules/copilot/application/tools/registry.py`:
    - Renombrado `ROUTE_TOOL_MAP` estático a `_BASE_ROUTE_TOOL_MAP`.
    - Implementado `_build_route_tool_map()` análogo a `_build_tool_groups()`: itera `discover_providers().values()`, por cada `provider.routes()` ProviderRoute extiende `merged.setdefault(prefix, []).append(group)` dedup.
    - Module-level `ROUTE_TOOL_MAP = _build_route_tool_map()`.
    - Comentario inline explica B20-TP10 + cierre F1 promise.
- **GREEN confirm:**
  - 12/12 tests `test_route_tool_mapping.py` pass (9 pre-existing + 3 nuevos).
  - 1818/1818 tests `tests/modules/copilot/ + tests/architecture/` pass.
  - Live S10.4 con tp10_dummy: `'tp10_dummy' in ROUTE_TOOL_MAP['*']` ✓ + `test_dummy_tool` en `get_tools_for_route("/copilot")` ✓ + tool fires sin tocar `tools/registry.py` excepto la línea structural del fix.
- **Regression coverage:** `TestProviderRouteMerging` 3 tests garantizan que regresión a `ROUTE_TOOL_MAP` estático rompe CI. Synthetic providers via monkeypatch — independiente del tp10_dummy filesystem lifecycle.

## Aprendizajes para TP11

- **Phase doc validation gate.** B21-TP10 destapó que el phase doc TP10 original tenía paths obsoletos (`application/providers/discovery.py` no existía), Protocol shape wrong (4 plain attrs vs 8 métodos), gotcha de naming invisible (`_test_provider` skipped por convention scan). Para TP11 (end-to-end UX), validar contra UI shell live + redesign learnings F11 antes de ejecutar — los UX heuristics rotan más rápido que docs.
- **F1 plug-in pattern requiere ambos: tool_groups merge + routes merge.** Para futuras integraciones de módulos, el dev necesita declarar `routes()` además de `tool_groups()`. Sin `routes()`, la herramienta queda en TOOL_GROUPS pero invisible para LLM. Considerar agregar a CLAUDE.md como pattern recordado para módulo nuevo.
- **Boot-time discovery + lru_cache implican restart obligatorio para module add/remove.** Para TP11 e2e UX si hay flow donde admin enable/disable feature flag impacta provider visibility, necesario surface "requires restart" en UI o documentación. Para flows que solo cambian behavior dentro de tools existentes (no add/remove tools), no aplica.
