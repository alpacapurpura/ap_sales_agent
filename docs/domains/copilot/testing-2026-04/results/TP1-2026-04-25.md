## Failures + root cause + fix aplicado

### A2 (heredada) — `"hola"` clasificaba LLM, no rule

- **Síntoma:** routing_log mostraba `classifier_used='llm'` con confidence=0.9, reason=`greeting` para mensajes triviales (4 chars).
- **Trace evidence:** 4 turns pre-fix, todos `tier=nano, classifier=llm`. RuleClassifier devolvía `None` siempre en chat.
- **Root cause:** `DEFAULT_ROUTING_POLICY.rules[priority=30]` tenía `max_tools=0`. En chat overlay siempre hay ≥26 tools del registry → guard `req.available_tool_count > rule.max_tools` falla → rule descartada → cascada a LLMClassifier.
- **TDD fix:**
  - **RED**: `tests/modules/copilot/test_router_factory.py::test_short_msg_routes_nano_with_tools_available` con `ExplodingLLM` que arroja si se invoca.
  - **Fix arquitectónico**: removido `max_tools=0` de la rule en `domain/routing_policy.py` (reason kept como `short_msg_no_tools` por continuidad telemetry).
  - **Domain test** updated: `test_short_msg_no_tools_nano_rule_exists` ahora asserts `rule.max_tools is None`.
  - **GREEN**: 20/20 routing tests + 1715/1715 copilot+arch suite.
- **Verificación runtime:** post-fix 8 turns batch — todos `classifier=rule, tier=nano, confidence=1.0, reason=short_msg_no_tools`.

### B1 (nuevo) — `cache_hit_rate` y `cached_input_tokens` no persistían en `turn_end.data`

- **Síntoma:** SQL `SELECT data->>'cache_hit_rate' FROM copilot_trace_event WHERE event_type='turn_end'` devuelve siempre `NULL`. Admin `/copilot-routing` cache curve sólo poblada para subset de turns. Investigación confirmó que el **structlog** `copilot_turn_usage` SÍ tenía los datos (avg cache hit 0.99-0.999) — el bug era persistencia en JSONB.
- **Trace evidence:** F8 promesa: "cache instrumentation lives in `UsageAccumulator.as_log_dict()`". `chat.py:725-735` construía un dict literal con sólo `total_tokens`+`model`, ignorando `cached_input_tokens`/`cache_hit_rate`/`cost_usd`.
- **TDD fix:**
  - **RED**: `tests/modules/copilot/test_turn_end_trace_data.py::TestBuildTurnEndData` (3 tests: cache metrics, stream shape, zero-prompt edge).
  - **Fix arquitectónico**: extraje helper `_build_turn_end_data(usage, acc)` en `chat.py` que mergea `usage.as_log_dict()` con stream-shape fields. Anchor: `[COPILOT-CACHE-PREFIX-F8]`.
  - **GREEN**: 3/3 nuevos + 1715/1715 suite intacta.
- **Verificación runtime:** post-fix 10 turns warmup — 8 con `cache_hit_rate=0.999` persistido en JSONB, 2 con `cache_hit_rate=0.0` por rate limit (sin usage_metadata recolectada).

### B2 (nuevo) — turn_end emite con `total_tokens=0` cuando stream falla a media corrida

- **Síntoma:** 2/10 turns post-fix con `data->>'total_tokens'='0'` y `data->>'model'='gpt-4o'` (default). Duración 28-43s. Sin `node_exit model` en trace timeline.
- **Trace evidence:** turn_end SÍ emitido (recorder OK), pero `usage.update_from_event()` NO se ejecutó porque el LLM call falló con `openai.RateLimitError` 429 y el deep_agent harness lo trapeo silently via `langgraph.prebuilt.tool_node._handle_tool_error`.
- **Root cause:** OpenAI tier 1 TPM = 30000. System prompt copilot pesa 17.5k tokens. Cualquier batch >1.7 turns/min gatilla rate limit; el LLM call retrya internamente con backoff hasta 60s, eventualmente succeede o devuelve error → en ambos casos `update_from_event` no captura el AIMessage.
- **NO fix arquitectónico Nicolify aplicado**: la causa raíz es **constraint billing OpenAI tier**. El comportamiento del recorder (emitir turn_end aunque la usage esté vacía) es correcto — alternativa (no emitir) sería peor para observability.
- **Recomendación**: bumpear org tier OpenAI o reducir system prompt copilot (F-pos).
- **Detection signal sugerido para admin**: agregar alerta cuando `(turn_end.data->>'total_tokens')::int = 0 AND duration_ms > 10000` se repite >5x/hora — proxy de rate limit pressure.

### B3 (nuevo) — `calculate_cost` no aplica cache discount

- **Síntoma:** `cost_usd` reported en `copilot_turn_usage` log + `turn_end.data` calcula full `prompt_tokens × input_rate`. Real billing OpenAI cobra `cached_input_tokens × cached_rate (0.5×input)` + `(prompt_tokens - cached) × input_rate`. Con cache hit 99% el log overestima ~50%.
- **Trace evidence:** `usage_tracking.calculate_cost(prompt_tokens=17554, completion_tokens=11, model="gpt-4o-2024-08-06")` = $0.044. Real con cache = $0.022.
- **NO fix aplicado en TP1**: scope arquitectónico cruza pricing dict + signature update + admin reads. Documentado como recomendación en `phases/TP1-*.md` antipatterns + abajo en §Recomendaciones.
