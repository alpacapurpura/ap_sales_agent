## Failures + root cause + fix aplicado

### B12-TP7 — Qdrant client/server version mismatch (404 on query_points)

- **Síntoma S7.2 inicial:** `qdrant_client.http.exceptions.UnexpectedResponse: Unexpected Response: 404 (Not Found)` en `MarketingKbStore.search → client.query_points`.
- **Trace evidence:** dev container `visionarias_qdrant` pinned a `qdrant/qdrant:v1.7.3` (docker-compose.yml line 345). qdrant-client `>=1.13.3` (requirements-runtime) instaló 1.17.1 que emite el endpoint `/points/query` (introducido en server 1.10). Server 1.7.3 → 404.
- **Root cause arquitectónico:** F10 nunca corrió contra Qdrant real — su test suite usa `QdrantClient(":memory:")` que tiene API completa client-side. Bump server pasaría por sequential upgrade 1.7→1.8→...→1.16 (Qdrant requiere upgrades consecutivos), riesgo cross-module (sales_agent + brand collections vivas).
- **TDD fix scope-able:**
  - **Path elegido (minimum change, no toca otros módulos):** httpx wrapper REST `/collections/{name}/points/search` que funciona en server 1.0+ universal.
  - `marketing_kb_store.py::MarketingKbStore.search` — try `client.query_points` → on `UnexpectedResponse` con "404", fallback `_search_via_rest` (httpx POST con auth headers + `must` filter shape).
  - `_hit_to_dict` + `_rest_point_to_dict` helpers module-level normalizan ambos paths a la misma shape pública.
  - Comentario inline `B12-TP7` referencia esta entrada, F-pos puede ripear branch cuando docker-compose bumpee Qdrant a server compat con qdrant-client major (≥1.16).
  - **GREEN:** S7.2 8/8 recall=1.0; S7.3 p50=423ms.

### B13-TP7 — CopilotJudge prompt hardcoded canonical 4 dims, ignora dimensions override

- **Síntoma S7.6 inicial:** `weekly_rag_eval` log dice `judge_avg=None`. SQL probe: `extra_metadata.judge_dimensions` = `{retrieval_relevance: null, citation_accuracy: null, answer_groundedness: null, completeness: null}` con `judge_models=["gpt-4o-mini"]`.
- **Trace evidence:** judge_models populated → real LLM call ejecutó. Pero todos dim scores = null → parser tomó branch `_failure_result` con `metadata.error="missing_dimension:retrieval_relevance"`.
- **Root cause arquitectónico:** `judge.py::_SYSTEM_PROMPT_ES` static constant hardcoded para canonical 4 dims. Cuando `CopilotJudge(dimensions=RAG_DIMENSIONS)` se construye, `self.dimensions` tracker está bien pero el prompt sigue pidiendo canonical → LLM devuelve canonical → `parsed.get("retrieval_relevance")` → None → fail. F11.5 nunca cerró este loop porque su test `test_copilot_rag_eval.py` mockea CopilotJudge.
- **TDD fix:**
  - **RED:** 4 nuevos tests en `tests/modules/copilot/test_copilot_judge.py`:
    - `test_rag_dimensions_prompt_lists_rag_rubric`
    - `test_judge_with_rag_dimensions_returns_scores_not_zeros`
    - `test_judge_with_rag_dimensions_alphabetical_order_in_prompt`
    - existing `test_system_prompt_in_spanish_neutro` refactored a usar `build_system_prompt(CANONICAL_DIMENSIONS)`.
  - **Arquitectura (rubric registry + dynamic prompt builder):**
    - `_DIMENSION_RUBRICS: dict[str, str]` registry con 8 entries (4 canonical + 4 RAG). Cada entrada es bullet body (sin ordinal prefix).
    - `build_system_prompt(dimensions: Sequence[str]) -> str` rendera prompt para dims requeridos, alfabetizando inside (bias mitigation), validando unknown dims raise `ValueError`. JSON shape generado dinámicamente. `brand_coherence` rule sólo emit si dim presente.
    - `evaluate()` ahora llama `build_system_prompt(self.dimensions)` en vez de constante estática.
    - `_SYSTEM_PROMPT_ES` removido del módulo + del `__all__`.
  - **GREEN:** 16/16 judge tests pass; S7.6 retry → judge_avg=4.84 + 4 dims populated; S7.5 real output → avg=5.00.
