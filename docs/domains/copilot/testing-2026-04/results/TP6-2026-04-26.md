## Failures + root cause + fix aplicado

### B7-TP6 (NUEVO TP6) — Voseo cross-channel: AGENT (Kimi K2.6 thinking-disabled) lapsa en voseo pese a "Tuteas al usuario" en system prompt

- **Síntoma run inicial:** 10 voseo hits en 5/16 scenarios — `podés / Tenés / Empezá / vos / Querés / sabés` aparecían en outputs WA / email / SMS / chat.
- **Trace evidence:** `copilot_trace_event` muestra outputs llegando al usuario con voseo. Tools=[] en muchos turns (AGENT generaba prosa directa sin call).
- **Root cause arquitectónico:**
  1. `copilot_system_static.j2` decía "Tuteas al usuario" — frase ambigua que Kimi K2.6 (thinking-disabled, instruction-following débil) interpreta como "tuteo argentino" tan válido como "tuteo neutro".
  2. `synthesizer.py:_empty_window_reply` y `:_unknown_intent_reply` (A2 heredada TP3+TP4) — strings static fallback `"¿Querés…?"` `"¿Podés reformularla…?"` user-facing.
  3. AGENT lapses ocasionales aunque prompt sea explícito (medido: con prompt strengthen, voseo cae 10→1, no 0).
- **TDD fix:**
  - **RED:** `tests/modules/copilot/test_system_prompt_neutro_latam.py` — 12 tests cubren static.j2 invariants + tools_hint.j2 channel keywords + synthesizer fallback strings.
  - **Arquitectura (3 capas defensa):**
    1. `copilot_system_static.j2` — explícito "español neutro latinoamericano (LatAm)" + glosario voseo→neutro + ejemplo CORRECTO/PROHIBIDO contraste.
    2. `synthesizer.py` — fallback strings `Querés→Quieres`, `Podés→Puedes`.
    3. `output_sanitizer.py::correct_voseo_in_text` — regex map 50+ formas voseo→neutro con preservación de capitalización. Last line of defense post-LLM.
    4. `chat.py` propaga `user_msg=message` al sanitizer (2 callsites).
  - **GREEN:** 0/36 voseo en outputs reales (matrix + stress).

### B8-TP6 (NUEVO TP6) — SMS overflow: AGENT llama `format_for_channel` pero ignora el `content` truncado

- **Síntoma run inicial:** 3/4 SMS scenarios devuelven 219/285/311 chars (target ≤160).
- **Trace evidence:** `SELECT count(*) FROM copilot_trace_event WHERE event_type='tool_call' AND name='format_for_channel'` post-matrix run = **22 calls** (AGENT SÍ llama tool). Tool returns `content` truncado a 160 chars + warnings=['truncated']. Pero AGENT emite su draft ORIGINAL como respuesta final, ignorando el `content` del tool.
- **Root cause:** Kimi K2.6 thinking-disabled tiene instruction-following débil para "USA EXACTAMENTE el campo `content` del JSON devuelto". Prompt-strengthen ayuda parcialmente (3→2 overflows) pero no llega a 0.
- **TDD fix arquitectónico (alineado con F7 design):**
  - **RED:** `tests/modules/copilot/test_output_sanitizer_channel_and_voseo.py` — 21 tests cubren `correct_voseo_in_text` + `detect_channel_in_user_msg` + `enforce_channel_format_if_needed` + composition.
  - **Arquitectura (safety net deterministic en sanitizer):**
    1. `output_sanitizer.py::detect_channel_in_user_msg(user_msg)` — regex sobre keywords (`whatsapp / sms / email / telegram / instagram_dm / voice / IG DM`). Devuelve canonical channel id o None.
    2. `output_sanitizer.py::enforce_channel_format_if_needed(text, user_msg)` — si user pidió canal ≠ chat, aplica `format_for_channel_impl(content=text, channel_id=...)` deterministicamente. **Idempotent**: si AGENT ya emitió canonical content (= tool result), no-op.
    3. `output_sanitizer.py::sanitize_assistant_text(text, user_msg=...)` — agrega 2 nuevas pasadas (voseo + channel) post-JSON-strip.
    4. `chat.py::_run_graph_stream` agrega kwarg `user_msg`, propaga a `sanitize_assistant_text` en line 909 (block_end finalize).
    5. `chat.py::_sanitize_ai_messages` agrega kwarg `user_msg`, propaga a sanitizer en line 778 (persistence).
    6. `chat.py::stream_chat` pasa `user_msg=message` a `_run_graph_stream`.
  - **GREEN:** 10/10 SMS ≤160 + 10/10 WA sin md noise (stress).

### Mejora colateral: prompt strengthening `copilot_system_tools_hint.j2`

- Agregada sección "Salida por canal — `format_for_channel`" cuando el tool está bound (`{% if available_tools and 'format_for_channel' in available_tools %}`).
- Detalla flujo obligatorio (1.draft → 2.tool call → 3.usar `content` field verbatim) + límites por canal + prohibición explícita de combinar `content` con texto propio.
- Reduce dependencia del safety net (medido: con strengthen sin sanitizer, SMS 4→2 overflows; con strengthen + sanitizer, 0).

- **Sanitizer último escalón > prompt-trust con Kimi K2.6 thinking-disabled (B8-TP6)**: El AGENT lapsa instructions ~50% del tiempo aún con prompts maximalmente explícitos. Para targets hard-fail (SMS ≤160, WA sin md noise, regla 11), F-pos siempre debe agregar safety net deterministic en sanitizer/post-process. F10 RAG citation accuracy (target ≥4.0) puede tener issue similar — si AGENT cita pero re-paraphrasea sin source mention, considerar inyectar citation footer post-LLM si tool `knowledge_search` devolvió chunks.

Para TP7 RAG, contar `tool_call name='knowledge_search'` rows NO es prueba de retrieval funcional — verificar que los `chunks` retornados aparezcan en la respuesta final (regex match o judge dim).
