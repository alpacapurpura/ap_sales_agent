## Failures + root cause + fix aplicado

### B14-TP8 — `MarketingKbStore.stats()` AttributeError on `info.vectors_count`

- **Síntoma:** Native script + admin /marketing-kb tab → `AttributeError: 'CollectionInfo' object has no attribute 'vectors_count'` al llamar `stats()`.
- **Trace evidence:** `qdrant_client.http.models.CollectionInfo` schema 1.17.x dropped `vectors_count` field. Inspect: `['status','optimizer_status','warnings','indexed_vectors_count','points_count','segments_count','config','payload_schema','update_queue']` — no `vectors_count`.
- **Root cause arquitectónico:** F10 stats() retornaba `{vectors_count, points_count, status}` confiando en CollectionInfo Pydantic shape. Qdrant client bump 1.17 (REST endpoint diff cubierto en B12-TP7) también eliminó `vectors_count` del response model. Para dense single-vector points ambos son siempre iguales (`points_count == vectors_count`).
- **TDD fix:**
  - **RED:** `test_stats_returns_points_count_status_no_attribute_error` en `tests/modules/copilot/test_marketing_kb_store.py` (in-memory store con 2 chunks upsert → llama stats(), asserta `points_count==2 + status=="green"` + `error not in stats`).
  - **Arquitectura:** `marketing_kb_store.stats()` drop `vectors_count` del return; `points_count` = canonical row count (1 vector por point en dense single-vector setup). Comentario inline `B14-TP8`.
  - **Admin marketing_kb.py:** drop col2 "Vectores" (eliminada del dict) — quedan 3 cols (Colección / Puntos / Status). UX ligeramente más compacta, semántica idéntica.
  - **GREEN:** 17/17 tests pass + live `MarketingKbStore().stats()` retorna `{collection: nicolify_marketing_kb, points_count: 304, status: green}`.

### B15-TP8 — `node_trace` drops `run_id` + `parent_ids` → tree no reconstruible

- **Síntoma S8.4 inicial:** SQL probe a `copilot_trace_event` para turn nuevo → `parent_span_id` NULL en TODOS los rows (incluyendo node_enter/exit). Plan §S8.4 exige "tree reconstruible (parent_span_id → span_id chain coherente)" + plan §Targets marca "broken span tree" como hard fail.
- **Trace evidence:** `node_trace.py::emit_node_trace_event` llamaba `record(event_type=..., name=..., data=...)` sin propagar `event['run_id']` ni `event['parent_ids']`. LangGraph `astream_events(v2)` yield ambos por evento (run_id pareado para `on_chain_start`/`on_chain_end` del mismo node + parent_ids = chain ancestral).
- **Root cause arquitectónico:** F9 docstring (`trace_recorder.py`) prometía "child events reference the parent via parent_span_id so LLM → tool → LLM chains reconstruct". El recorder accept `span_id` + `parent_span_id` como kwargs opcionales, pero el caller (`emit_node_trace_event`) NUNCA los pasaba — gap entre la promesa del recorder y el hookup del emitter. F11.5 + F9 cerraron quality gates internos sin nunca exercise live tree reconstruction.
- **TDD fix:**
  - **RED:** 3 nuevos tests en `tests/modules/copilot/test_node_trace_emission.py`:
    - `test_propagates_run_id_as_span_id_for_pairing_enter_exit` — node_enter + node_exit del mismo run_id comparten span_id.
    - `test_propagates_immediate_parent_run_id_as_parent_span_id` — `parent_ids[-1]` mapea a parent_span_id.
    - `test_omits_run_id_kwargs_when_event_lacks_them` — defensive backward-compat (eventos viejos sin run_id no rompen).
  - **Arquitectura:** `node_trace.py` extrae `event.get("run_id")` + `event.get("parent_ids") or ()` ; agrega `extra_kwargs["span_id"]` si run_id; agrega `extra_kwargs["parent_span_id"] = parent_ids[-1]` si parent_ids. Llamada `record(**extra_kwargs)` propagación condicional. Comentario inline `B15-TP8`.
  - **GREEN:** 10/10 node_trace tests pass + live re-trigger turn multi-step → parent_span_id populated en 9/9 node events + node_enter/exit pares comparten span_id. Tree reconstruible via parent_span_id chain (root: deep_agent run id `019dcb13-9e2a-7542-802a-dc41d0bf7979`).

### B17-TP8 — `accuracy` rubric punishes scope-appropriate refusal

- **Síntoma S8.8 inicial:** Golden `error_recovery_003_off_topic` (user="¿Cuál es la capital de Francia?") judged avg=2.75 — utility=2 ("no resuelve la intención del usuario"), accuracy=3 ("no responde a la pregunta factual"). Hard fail debajo threshold 3.5. Plan §Targets marca "0 voseo" hard fail pero también "20/20 pass" target.
- **Trace evidence:** Real LLM judge response JSON. La respuesta del copilot ("Esa pregunta queda fuera del scope ... ¿Hay algo en alguna de esas áreas?") es polite redirect SIN opciones concretas. Judge interpreta "no contesta capital de Francia" como falla utility + accuracy.
- **Root cause arquitectónico:** Dos issues compuestos:
  1. **Golden expected_output muy vago** — invita "¿hay algo en marketing?" sin opciones concretas → utility=2.
  2. **Accuracy rubric pre-B17 ambiguo** — "Score 5 = factual + verificable; Score 1 = alucinación o contradice contexto". No reconoce explícitamente "scope-appropriate refusal" como factual. Judge LLM aplica accuracy a pregunta original (capital France) en vez del refusal.
- **TDD fix dual:**
  - **(a) Golden upgrade:** `error_recovery_003_off_topic.expected_output` actualizado a redirect con 3 anclas concretas (revisar posicionamiento StoryBrand / diseñar headline / analizar métricas captación) + cierre "¿Por cuál empezamos?". Comentario referencia B17-TP8.
  - **(b) Rubric arquitectónico:** `_DIMENSION_RUBRICS["accuracy"]` extendido — "Score 5 = factual + verificable, **o redirect honesto cuando la pregunta queda fuera del rol del asistente** (marketing, ofertas, marca, datos del negocio); score 1 = alucinación, dato falso o contradice contexto".
  - **GREEN:** Re-run judge sobre golden actualizado → 20/20 pass. Full suite `test_copilot_judge.py` 16/16 pass (rubric change no rompe assertions estructurales).
