**Gotcha 2: Migration idempotency**
- Raw SQL UPDATE with WHERE clause guards idempotency: `UPDATE tenants SET col=NULL WHERE col IS NOT NULL` runs safely 2x (second run changes nothing).

- `Field(default=None, deprecated=True, exclude=True)` must all three be set together for deprecated tenant keys

**Gotcha 4: Tenant isolation in code**

- But repositories: still must filter tenant_id on create/update (where calls tenant_repository.create(tenant_id, ...))
