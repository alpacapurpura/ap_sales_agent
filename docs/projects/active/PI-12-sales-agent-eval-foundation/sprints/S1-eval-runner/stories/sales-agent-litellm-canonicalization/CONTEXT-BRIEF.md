**T-1.bis: Callback handler test fix (LiteLLM cost bridge)**  
**Status:** READY (real bug diagnosis, test-side fix only)  
**Origin:** Commit 5856be4d (T-1, 2026-05-05 06:30Z) introduced LiteLLM CustomLogger bridge. Cost is now consumed via `pop_cost(litellm_call_id)` from thread-safe TTL cache (60s), NOT computed at runtime via `calculate_cost()` per acceptance A4 of T-1.

**Symptom:** 2 failing callback-handler tests mock `LLMResult` WITHOUT injecting `litellm_call_id` in response_metadata:

Both assert `cost_usd > 0` but get `None` → `TypeError: '>' not supported between NoneType and int`.

**Root cause:** Test fixtures incomplete. `_extract_litellm_call_id()` returns `None` → handler's `pop_cost()` call returns `None` → `cost_usd` persisted as `NULL` (not 0). Tests don't pre-stash cost via `_stash()` pattern to bridge the gap.

**Fix strategy:** Migrate tests to inject `litellm_call_id` in mock response_metadata + pre-stash cost via `cost_recorder._stash(call_id, cost)` in test setup. ZERO changes to cost_recorder.py or base_callback_handler.py code (both correct per T-1 architecture).

Solution: (1) inject `litellm_call_id` into the mock response_metadata, (2) pre-stash the cost in test setup via `cost_recorder._stash(call_id, cost)` (it's a module-level TTL cache, and using private helper in test is acceptable for bridge priming). Add a docstring explaining why — it mirrors the real bridge architecture (LiteLLM CustomLogger stashes via `litellm_call_id`, LangChain handler retrieves via the same key).
