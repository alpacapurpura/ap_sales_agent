## 14. Free-form notes — what I'd tell a smart colleague

**What you need to know before shipping T-4:**

1. **Langdetect lazy import is non-negotiable.** The rule is clear from the prompt: `importlib.import_module("langdetect")` with try/except (LangDetectException + ImportError) → fallback "unknown". Top-level `import langdetect` in assertions.py will get flagged by lint (and maybe arch fitness test). Keep prod surface clean; langdetect lives only in `[project.optional-dependencies].evals`.

2. **Tool names are NOT hardcoded.** B4 spec lists 13 forbidden tool names (e.g., `send_email`, `schedule_meeting`, `create_payment_link`). These must match real names from `src/modules/sales_agent/application/tools/registry.py`. If you hardcode string literals, you risk silent mismatch when tool names get refactored (happened before). The assertion function should accept a list; test data provides the canonical list.

3. **Cost assertion MUST filter tenant_id.** When `assert_cost_recorded(run_id, ...)` queries `sales_agent_llm_call` table, the WHERE clause must include `tenant_id == expected_tenant_id`. Cross-tenant leakage is a security audit fail. The fixture provides Visionarias UUID; use it.

4. **Composition over subclassing for callbacks.** T-3 already established the pattern: TrajectorySpy is a `BaseCallbackHandler` added to the callbacks list at invoke time, not a subclass of the sales_agent handler. You're reading spy output (specialist_history, tool_calls, duration_ms), not writing. This is clean and anti-duplication compliant. Don't be tempted to subclass.

5. **Spanish neutro in error messages.** Error messages from assertion failures (e.g., OutputAssertionError.observed) should be in Spanish LATAM if user-facing (dev debugging). No voseo (`podés`, `tenés`). The brief has the glosario if needed.

6. **Five layers, five exception types.** The hierarchy is intentional for downstream debugging. T-5 smoke test will catch which layer failed + exact mismatch (observed vs expected). This makes troubleshooting fast when agente regresses. Don't collapse exception types.

7. **Story 7 placeholder is real.** `assert_voice_fidelity` raises `NotImplementedError`. This is a safety gate: if T-5 smoke test accidentally calls it (shouldn't happen), the test will error clearly instead of silently skipping voice validation. Future Story 7 will implement the grader; smoke test will add that call.

8. **No seeding, no fixtures writing to DB.** The eval harness is read-only for assertions. T-2 fixtures provide the Visionarias tenant precondition (skip if missing). T-3 TrajectorySpy writes artifacts (trace.json, assertions.json) to `_artifacts/` (gitignored). T-4 queries existing DB tables written by T-3 callback handler. Don't create new fixture that seeds cost rows; rely on T-3's real LLM calls writing them.
