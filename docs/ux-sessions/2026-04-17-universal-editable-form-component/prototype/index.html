Componente Universal Editable

Reemplazo del patrón preview + form modal. El preview es el form. Copilot siempre sabe qué vista y campo mira el usuario.

Principios del componente (invariantes en las 3 variantes)

  • ✓ 1 componente por entidad. No hay `Preview` separado del `Form`.
  • ✓ Cada campo envuelto en <EditableField> (evolución de WithCopilot): expone fieldId, fieldPath, fieldLabel, currentValue al store copilot.
  • ✓ Copilot lee focusedField del store → FocusBar muestra "Editando: Marca › Identidad › Misión".
  • ✓ Desde chat: mencionar un campo → tool update_field dispara copilot:field-update → highlight verde + valor aplicado.
  • ✓ Schema-driven: un JSON por entidad (brand-identity.schema.json) + un resolver de campos renderea todo. Migración: brand → offer → buyer_persona → todo.

3 variantes a comparar

VARIANTE A

Click-to-edit (Notion)

Leído como card visual rico. Click en un valor → se vuelve editable in-place. Items compuestos → card expande.

✓ Visual limpio · ⚠️ 1 click extra para editar
VARIANTE B

Always-editable (Airtable)

Inputs visibles siempre, tipografía discreta. Cero clicks para editar. Items compuestos → drawer lateral.

✓ Edición sin fricción · ⚠️ Densidad visual alta
VARIANTE C

Row + Detail Pane (Linear)

Lista compacta de campos/items a la izq. Click → panel de detalle a la der. Edita ahí. Copilot ve el panel activo.

✓ Escalable a docenas de campos · ⚠️ Requiere 2 columnas

Cómo evaluar

  1. Abre cada variante.
  2. En cada una: click en un campo de Identidad (ej. misión) → observa el copilot derecho: la FocusBar dice qué campo editás.
  3. Click en Agregar miembro en Team → observa el patrón de edición de items compuestos.
  4. En chat (columna der) probá: "cambia la misión" → mirá cómo aplica el cambio + badge IA.
  5. Volvé y decime cuál + qué ajustarías.
