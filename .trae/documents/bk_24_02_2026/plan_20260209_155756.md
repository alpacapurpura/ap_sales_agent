# Mejora de UX/UI y Lógica para Ofertas tipo Cohorte

Basado en el análisis del código actual (`ProgramDetails` y `ProgramForm`) y la investigación de patrones UX (Skool), propongo el siguiente plan de implementación para transformar la sección "La Solución".

## 1. Backend: Actualización del Esquema (`schema.py`)
Necesitamos enriquecer el modelo `ProgramDetails` para soportar los nuevos campos de logística y calendario.

*   **Nuevo Campo:** `registration_end_date` (datetime, opcional) - Para cierre de inscripciones.
*   **Nuevo Campo:** `is_end_date_estimated` (bool) - Para marcar la fecha fin como tentativa.
*   **Nuevo Campo:** `schedule` (List[SessionDetails]) - Estructura para reemplazar el texto plano.
    *   *Sub-modelo `SessionDetails`:* `{ name: str, day: str, time: str, duration: int }`.

## 2. Frontend: Refactorización de `ProgramDetailsForm`
Transformaremos el formulario monolítico en una experiencia más modular y lógica.

### A. Reordenamiento y "Requiere Aplicación"
*   **Acción:** Mover el switch `is_application_required` inmediatamente debajo de `structure_type`.
*   **Mejora UX:** Convertirlo en una "Card de Decisión" visualmente destacada (Borde azul/ícono) en lugar de un switch simple, ya que define el flujo de venta (High Ticket vs Venta Directa).

### B. Gestión de Fechas (Start/End/Deadline)
*   **Separación Fecha/Hora:** Reemplazar el `SmartDateTimePicker` único por:
    *   Selector de Fecha (Calendario).
    *   Selector de Hora (Input Time) separado.
    *   *Lógica:* Si no se pone hora, se asume 00:00 (o TBD).
*   **Cierre de Inscripciones:** Nuevo campo opcional.
    *   *UX:* Un checkbox "¿Tiene fecha de cierre diferente al inicio?" que revela el selector. Si no se marca, backend asume `start_date`.
*   **Fecha Fin Estimada:** Selector de solo fecha + Checkbox "Fecha estimada".

### C. Nuevo Módulo "Horario de Sesiones" (Inspiración Skool)
En lugar de un texto plano, implementaremos un **"Session Builder"** (Lista dinámica):
*   Permitirá agregar N sesiones recurrentes.
*   **Campos por fila:**
    *   Título (ej. "Mentoria Grupal", "Q&A Técnico").
    *   Día (Lunes, Martes...).
    *   Hora (Selector de hora).
*   **Visualización:** Se mostrará como una "Agenda Semanal" limpia en lugar de JSON o texto.

## 3. Pasos de Implementación
1.  **Backend:** Modificar `ProgramDetails` y crear modelo `SessionDetails`.
2.  **Frontend:** Crear componente `SessionScheduleBuilder` (uso de `useFieldArray`).
3.  **Frontend:** Actualizar `ProgramDetailsForm` con la nueva lógica de fechas y reordenamiento.
4.  **Verificación:** Probar guardado y validación de tipos.
