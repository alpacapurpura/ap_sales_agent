# Plan de Implementación: Offer Lifecycle & Validation

Siguiendo tu instrucción, reutilizaremos la lógica de "Flight Check" existente para validar la activación, mientras relajamos el esquema para permitir guardar borradores incompletos.

## 1. Actualización de Enums (Backend & Frontend)

Expandiremos el ciclo de vida de la oferta para soportar los nuevos estados.

*   **Backend** (`backend/src/core/domain/offer_enums.py`):
    *   Actualizar `OfferStatus` para incluir: `DRAFT`, `ACTIVE` (reemplazando o mapeando ALWAYS_ON), `PAUSED` (o STOPPED), `ARCHIVED`.
*   **Frontend** (`frontend/src/lib/api/offer.ts`):
    *   Asegurar que el enum `OfferStatus` coincida: `DRAFT`, `ACTIVE`, `PAUSED`, `ARCHIVED`.

## 2. Relaxed Schema para Borradores (Frontend)

Para permitir "Guardar Borrador" en cualquier momento, debemos modificar las reglas de validación del formulario *base*.

*   **Archivo**: `frontend/src/features/offer-studio/types/schema.ts`
*   **Cambio**: Modificar `OfferSchema` para que campos como `headline_promise`, `primary_outcome`, `time_to_value` sean `.optional()` o `.or(z.literal(''))`.
    *   *Nota*: Esto permite que `react-hook-form` acepte el estado actual del formulario sin bloquear el "Submit".

## 3. Reutilización del "Flight Check" (Frontend)

Usaremos la función existente `getOfferValidationStatus` en `offer-context-panel.tsx` como el **Gatekeeper** para la activación.

*   **Lógica**: Esta función ya valida que los campos tengan contenido real (ej: `length > 10`).
*   **Flujo**:
    *   Si el usuario hace click en "Guardar Borrador": Se usa el Schema relajado -> Éxito.
    *   Si el usuario hace click en "Publicar/Activar":
        1.  Ejecutar `getOfferValidationStatus(values)`.
        2.  Si `!isValid`, bloquear acción y mostrar el panel de errores (Flight Check).
        3.  Si `isValid`, cambiar `status` a `ACTIVE` y guardar.

## 4. UI: Barra de Acciones Inteligente (Frontend)

Modificaremos `OfferEditor` (`frontend/src/features/offer-studio/components/offer-editor.tsx`) para implementar la nueva barra de control.

*   **Componente**: Crear/Modificar la barra superior (Header).
*   **Estados de Botones**:
    *   **Borrador (DRAFT)**:
        *   `[Guardar Cambios]` (Secundario, siempre activo).
        *   `[Publicar Oferta]` (Primario, deshabilitado/tooltip si Flight Check falla).
    *   **Activo (ACTIVE)**:
        *   `[Guardar Cambios]` (Primario).
        *   `[Pausar]` (Peligro suave, cambia a PAUSED).
    *   **Pausado (PAUSED)**:
        *   `[Reanudar]` (Primario, cambia a ACTIVE).
        *   `[Archivar]` (Destructivo).

## 5. Backend Validation (Opcional pero recomendado)

*   Asegurar que el endpoint `PATCH /products/{id}` acepte los nuevos status.
*   El modelo Pydantic de entrada (`ProductUpdate`) ya es opcional, así que no requiere cambios mayores, solo soportar los nuevos valores de Enum.

---
**Resumen del Flujo de Trabajo:**
1.  **Update Enums**: Backend & Frontend.
2.  **Relax Schema**: Frontend Zod.
3.  **UI Update**: Implementar barra de acciones en `OfferEditor` conectada al `getOfferValidationStatus`.
