# Implementation Plan: "Wise Agent" Architecture (Execution vs. Evaluation)

This plan implements the separation of "Runner" (Sales) and "Evaluator" (Scoring) and prepares the "Data Flywheel" for future Reinforcement Learning.

## 1. Database Schema Upgrade (Data Flywheel)
We need to enrich `AgentTrace` to capture the "Trajectory" (State -> Action -> Reward) required for future RL (Agent Lightning).

### 1.1 Modify `AgentTrace` Model
Add the following columns to `services/db/models/observability.py`:
*   `action`: String (The specific tool/node decision, e.g., `qualifier`, `closer`).
*   `reward`: Float (The quantitative outcome of the step, e.g., `0.5`, `1.0`).
*   `feedback`: Text (Qualitative critique for Reflexion).

### 1.2 Update Repository
Update `services/db/repositories/audit.py` to handle these new fields in `create_trace`.

## 2. Implement "The Evaluator" (Separation of Concerns)
Instead of asking the Sales Agent to "sell and score" at the same time, we create a dedicated `Evaluator` node that runs silently after the response is generated.

### 2.1 New Node: `node_evaluator`
Create a new node in `core/agents/orchestrator/nodes.py` that:
1.  Takes the last turn (User Input + Agent Response).
2.  Uses a specialized "Judge" LLM (Low temperature, analytical prompt).
3.  Outputs: `fit_score` (+/-), `intent_score` (+/-), and `funnel_stage` update.
4.  Updates `AgentState` *without* generating a new message to the user.

### 2.2 New Prompt: `EVALUATOR_PROMPT`
Create a prompt in `core/agents/orchestrator/prompts.py` that instructs the LLM to act as a neutral judge, scoring the lead based on *behavior* and *data*, not "vibes".

## 3. Wiring the Graph
Update `core/agents/orchestrator/graph.py` to include the Evaluator.

**Current Flow:**
`Entry -> Router -> Sales -> Exit`

**New Flow:**
`Entry -> Router -> Sales -> Evaluator -> Exit`

## 4. Execution Steps

1.  **DB Migration**: Add columns to `AgentTrace` (using Alembic or direct SQL for dev).
2.  **Repo Update**: Update `AuditRepository`.
3.  **Prompt Creation**: Define `EVALUATOR_PROMPT`.
4.  **Node Implementation**: Code `node_evaluator`.
5.  **Graph Update**: Insert the node into the workflow.
6.  **Verification**: Run a conversation and check `agent_traces` for the new fields and `leads` table for updated scores.
