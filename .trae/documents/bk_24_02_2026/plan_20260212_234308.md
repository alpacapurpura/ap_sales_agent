# Migración a Arquitectura "Dynamic Sections" (Control Centralizado)

Este plan transformará el sistema actual (donde la estructura está "harcodeada" en el Frontend) a uno donde el Backend dicta exactamente qué secciones y en qué orden deben aparecer, dando control total desde los Prompts/Templates.

## 1. Backend: Definición de Estructura Dinámica

### A. Actualizar Esquemas Pydantic
Modificar `LandingPageConfig` para que `content` no sea un objeto rígido (`TransformerContent`), sino una lista de secciones polimórficas.
*   **Archivo**: `backend/src/core/domain/landing_page/schema.py`
*   **Cambio**: Crear modelos `LandingSection` (con `type` y `props`) y actualizar `content: List[LandingSection]`.

### B. Estandarización de Prompts (Jinja2)
Crear un "Meta-Prompt" que instruya a la IA a generar una **lista de bloques** en lugar de un XML plano.
*   **Archivo**: `backend/src/core/prompts/templates/dynamic_landing.j2` (Nuevo)
*   **Lógica**:
    > "Genera una lista de secciones para esta oferta.
    > Estructura JSON esperada:
    > `sections: [ { "type": "HeroSection", "props": { ... } }, { "type": "OfferSection", "props": { ... } } ]`"

### C. Actualizar `LandingGeneratorService`
Modificar el método `generate_landing_page` para procesar esta lista dinámica.
*   **Archivo**: `backend/src/services/landing_generator_service.py`
*   **Acción**:
    1.  Pedir a la IA JSON estructurado (lista de secciones).
    2.  Validar que los `types` de sección coincidan con los que Puck espera.

## 2. Frontend: Adaptador "Agnóstico"

### A. Simplificar `adapter.ts`
El adaptador dejará de tener lógica de negocio ("Si es Transformer, pon Hero luego PAS..."). Ahora solo será un traductor directo.
*   **Archivo**: `frontend/src/features/landing-builder/utils/adapter.ts`
*   **Lógica Nueva**:
    ```typescript
    config.content.sections.forEach(section => {
        addBlock(section.type, section.props);
    });
    ```
    *Esto significa que si mañana la IA decide (o tú le dices en el prompt) que ponga la Oferta primero, Puck lo renderizará primero sin cambios de código.*

## 3. Beneficios
1.  **Control Único**: Solo editas el prompt/template en el backend para cambiar la estructura de la landing.
2.  **Flexibilidad**: Puedes tener arquetipos que varíen según la oferta (ej. una oferta con 2 secciones de Testimonios si tiene mucha prueba social).
3.  **Menos Código Frontend**: Eliminamos la lógica de "mapeo manual" en TypeScript.
