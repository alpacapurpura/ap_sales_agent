# Arquitectura de Layout Independiente para Puck Editor

Has dado en el clavo. El problema de fondo no es CSS, sino **arquitectónico**. Puck está heredando el `layout.tsx` raíz de tu aplicación, que probablemente inyecta el Sidebar, el Header, los ThemeProviders y estilos globales que interfieren con el editor.

Para tener un editor "limpio" y profesional, debemos aislarlo completamente usando **Route Groups** de Next.js. Esto nos permite tener múltiples Layouts Raíz (`<html>` y `<body>` separados) en la misma aplicación.

## Plan de Refactorización

### 1. Crear el Grupo `(main)`

Moveremos toda la aplicación actual (excepto el editor) a un nuevo grupo. Esto encapsulará el layout "pesado" (Sidebar, Dashboard UI).

* **Acción**: Crear carpeta `frontend/src/app/(main)`.

* **Movimiento**: Mover `layout.tsx` (el actual raíz) dentro de `(main)`.

* **Migración de Rutas**: Mover las carpetas `(dashboard)`, `(public)`, `(app)`, `book`, `sign-in`, `sign-up`, `visit`, `forbidden` y `google-callback` dentro de `(main)`.

### 2. Aislamiento del Grupo `(editor)`

El editor ya está en `(editor)`, pero actualmente hereda el layout raíz. Al mover el layout raíz a `(main)`, `(editor)` quedará "huérfano" y necesitará su propio layout raíz.

* **Acción**: Crear `frontend/src/app/(editor)/layout.tsx`.

* **Contenido**: Este será un layout minimalista.

  * `<html>` y `<body>` limpios.

  * Sin Sidebar, sin Header global.

  * Solo `ClerkProvider` (auth) y `Toaster` (notificaciones).

  * Estilos base mínimos.

### 3. Ajuste de Archivos Raíz

* `globals.css` y `providers.tsx` se quedan en `src/app/` para ser importados por ambos layouts si es necesario, pero su impacto será controlado por cada layout.

## Estructura Resultante

```text
src/app/
├── (main)/                 <-- Tu App Principal (Dashboard, Web Pública)
│   ├── layout.tsx          <-- Layout con Sidebar, ThemeProvider, Fuentes
│   ├── (dashboard)/...
│   ├── (public)/...
│   └── page.tsx            <-- Landing home
├── (editor)/               <-- Tu "Segunda Solución" (Puck)
│   ├── layout.tsx          <-- Layout LIMPIO (Solo Auth + Editor)
│   └── editor/...
└── globals.css             <-- Estilos base
```

### Beneficios

1. **Independencia Total**: El editor no heredará márgenes, paddings ni colores del Dashboard.
2. **Performance**: El editor no cargará componentes innecesarios (Sidebar, UserMenu) de la app principal.
3. **Solución Definitiva al CSS**: Al tener su propio `<body>`, no habrá conflictos de especificidad con clases globales del Dashboard.
