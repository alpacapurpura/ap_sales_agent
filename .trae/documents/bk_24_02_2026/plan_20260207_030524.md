# Offer Canvas Final: Diseño Polimórfico y Educativo

Esta versión final incorpora la gestión de esquemas dinámicos (Polimorfismo) y una UI educativa estricta (Sin IDs técnicos).

## 1. Arquitectura de Componentes "Inteligentes"

Para resolver la complejidad de los 5 esquemas de detalles sin abrumar al usuario, usaremos componentes dinámicos.

### Componentes Educativos (UI Kit)
*   **`RichSelect`**: Un dropdown avanzado que nunca muestra el ID (ej. `FIXED_COHORT`).
    *   *Muestra*: Título ("Cohorte con Fecha Fija") + Descripción ("Curso con fecha de inicio y fin, todos van al mismo ritmo").
    *   *Uso*: Para `FulfillmentType`, `ProgramStructure`, `GuaranteeType`.
*   **`FieldInfo`**: Icono `(i)` circular que al hacer hover muestra un Tooltip explicativo con ejemplos.
    *   *Ejemplo*: En "Internal SKU", el tooltip dirá: "Código único para tu inventario. Ej: CURSO-INSTA-2024".

## 2. Layout del Canvas (Bento Grid 3-Columnas)

### ZONA A: Estrategia (Input para IA)
*   **Identidad**: Nombre, SKU.
*   **Avatar & Ángulos**:
    *   *RichSelect* para `AvatarPersona` (Principiante/Experto).
    *   *Nuevos Campos*: `marketing_pain_points` (Array) y `marketing_desires` (Array) para alimentar la IA.

### ZONA B: El Producto (Polimórfico)
Aquí reside la lógica compleja. La tarjeta central "Detalles Específicos" cambiará totalmente según el `OfferType`:

1.  **Si es Curso/Reto** → Carga `ProgramDetailsForm`
    *   Campos: Fecha Inicio/Fin, Plataforma (Circle/Skool).
2.  **Si es Servicio/Consultoría** → Carga `ServiceDetailsForm`
    *   Campos: Sesiones, Tiempo de entrega, Booking URL.
3.  **Si es Recurso/Producto** → Carga `ProductDetailsForm`
    *   Campos: Formato (PDF/Video), Descarga.
4.  **Si es Evento/Retiro** → Carga `EventDetailsForm`
    *   Campos: Ubicación, Alojamiento.
5.  **Si es Suscripción** → Carga `SubscriptionDetailsForm`
    *   Campos: Ciclo de facturación, Política de cancelación.

### ZONA C: Cierre y Ventas (Onboarding)
Mapearemos los campos existentes del Schema a una UI de decisión:

*   **"¿Cómo compra el cliente?"** (Mapea a `onboarding_action`):
    *   Opción A: **Compra Directa** (`CHECKOUT_LINK`) → Muestra input `checkout_page_url`.
    *   Opción B: **Agendar Llamada** (`CALENDAR_BOOKING`) → Muestra selector `calendar_type_id`.
    *   Opción C: **Aplicación/Formulario** (`INTAKE_FORM`) → Muestra input `onboarding_url`.
*   **Pricing & Garantía**:
    *   Uso de `RichSelect` para `GuaranteeType` explicándole al usuario qué implica "Action Based Refund".
