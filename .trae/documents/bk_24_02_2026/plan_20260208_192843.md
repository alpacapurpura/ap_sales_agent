# Plan de Corrección de Layout (Viewport Fit)

He identificado que el problema de scroll ("me puedo ir hasta abajo siendo la parte visible únicamente la parte superior") se debe a un conflicto de alturas: el `OfferEditor` intenta ocupar el 100% de la pantalla (`100vh-4rem`) pero está dentro de un contenedor con padding (`p-6` o `p-8`), lo que fuerza al navegador a crear un scroll en el cuerpo de la página (body scroll) en lugar de respetar los scrolls internos de las columnas.

## Solución Técnica: Ajuste de "Viewport Real"
Para lograr el efecto de "aplicación pantalla completa" dentro del Dashboard sin romper el layout, ajustaré el contenedor principal del editor.

### 1. Recálculo de Altura (Responsive)
Modificaré `frontend/src/features/offer-studio/components/offer-editor.tsx` para restar el espacio exacto que consume el entorno del Dashboard:

*   **Móvil**: `h-[calc(100vh-9rem)]`
    *   Descuenta: Header Móvil (64px) + Padding Layout (48px) + Margen seguridad.
*   **Escritorio**: `h-[calc(100vh-6rem)]`
    *   Descuenta: Padding Layout (64px) + Margen seguridad para que el editor "respire".

### 2. Maquetación y Estética (UI Polish)
Aprovecharé para encapsular el editor visualmente, como solicitaste ("revisada de experto maquetador"):
*   **Contenedor**: Añadiré `rounded-xl border shadow-sm bg-background` al div principal.
*   **Efecto**: El editor parecerá una "tarjeta flotante" o "ventana" dentro del dashboard, con bordes definidos, eliminando la sensación de que el contenido se "corta" o se desborda.

### 3. Verificación de Scroll Independiente
*   **Columna Izquierda (Formulario)**: Mantendrá `overflow-y-auto` para scrollear infinitamente el contenido.
*   **Columna Derecha (Contexto)**: Mantendrá su altura fija relativa al contenedor padre, asegurando que el panel de "Ayuda/Recursos" esté siempre visible y scrollee independientemente.

Este cambio es puramente de CSS/Clases y no afecta la lógica funcional (react-hook-form, estados, etc.).
