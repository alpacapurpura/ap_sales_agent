# Plan Optimizado: Landing Pages de Alto Rendimiento (SEO & Speed Focus)

Entendido. El objetivo cambia de "Flexibilidad Dinámica" a **"Rendimiento Extremo y SEO"**. Mantendremos la facilidad de edición, pero el resultado final será **HTML Estático/SSR Optimizado**, eliminando la carga de procesamiento cliente y minimizando el uso de recursos para soportar tráfico masivo.

## 1. Arquitectura de Datos (Backend)
*Igual que la propuesta anterior, ya que el JSON estructurado es la única forma mantenible de permitir que la AI y el Humano editen el contenido.*

*   **Modelos Pydantic**: `SqueezeContent`, `EventContent`, etc.
*   **Almacenamiento**: JSONB en Postgres.

## 2. Estrategia de Publicación "Zero-Bundle" (El Cambio Clave)

Para cumplir con "HTML Sencillo" y "Alto Tráfico", usaremos **React Server Components (RSC)** de Next.js de una forma específica:

### 2.1 Ruta Pública Ligera (`/p/[slug]`)
Esta ruta será **totalmente independiente** del dashboard administrativo.
*   **Rendering**: Usaremos `generateStaticParams` (SSG) o ISR (Revalidación Incremental). Esto significa que la página se construye **una sola vez** en el servidor y se sirve como HTML estático puro a los miles de visitantes. **Cero impacto en la Base de Datos** durante picos de tráfico.
*   **Zero-Client-JS**: Diseñaremos los componentes de las plantillas para que **no requieran hidratación de React** en el cliente (salvo elementos interactivos estrictamente necesarios como un formulario). El navegador recibirá HTML + CSS puro.
*   **SEO Técnico**: Inyección dinámica de `Metadata` (Title, Description, OpenGraph, Schema.org JSON-LD) basada en el contenido.

### 2.2 Motor de Plantillas (Frontend)
En lugar de componentes complejos, crearemos "Plantillas de Renderizado Puro":
*   `features/landing-builder/templates/server/SqueezeServerTpl.tsx`
*   Estas plantillas recibirán el JSON y devolverán HTML semántico limpio (`<header>`, `<main>`, `<article>`), optimizado para Google.

## 3. Flujo de Trabajo

1.  **Generación (AI)**: El backend crea el JSON (Copy + Estructura) basado en la oferta.
2.  **Edición (Visual)**: El usuario usa el editor (que sí carga React) para modificar textos y colores.
3.  **Publicación (Build)**: Al guardar, el sistema invalida la caché de esa URL.
4.  **Entrega (Venta)**: El tráfico de ads llega a la URL pública. Next.js sirve el HTML pre-renderizado. Carga instantánea, 100/100 en PageSpeed.

## 4. Paso a Paso Técnico

1.  **Backend**: Crear Modelos `LandingPage` y Endpoint de Generación AI (LangChain).
2.  **Frontend (Editor)**: Crear interfaz de edición visual (consume el JSON).
3.  **Frontend (Public)**:
    *   Crear ruta `app/(public)/p/[slug]/page.tsx`.
    *   Implementar **Metadata API** para SEO dinámico.
    *   Implementar `SqueezeTemplate` usando Server Components.
4.  **Optimización**: Configurar `next/image` y carga de fuentes para asegurar Core Web Vitals verdes.

Esta solución ofrece lo mejor de dos mundos: **Edición potente** (gracias al JSON) y **Entrega ultraligera** (gracias a Server Components/ISR).
