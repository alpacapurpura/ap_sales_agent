# Implementación de Gestión de Zonas Horarias y Formato de Fechas

## 1. Backend: Configuración de Tenant y Schema
### Objetivos
- Asegurar que el modelo de `Tenant` exponga la configuración de zona horaria.
- Establecer 'America/Lima' como default para el tenant 'visionarias'.

### Pasos
1.  **Actualizar Schema Pydantic (`backend/src/core/domain/schema.py`)**:
    - Modificar `TenantProfile` (o el esquema de respuesta pertinente) para incluir `timezone: str`.
2.  **Actualizar Dependencia/Servicio (`backend/src/api/dependencies.py` o Service)**:
    - Asegurar que al recuperar el Tenant, se extraiga `timezone` de `config_json` (default: "UTC").
3.  **Script de Migración (Script Python)**:
    - Ejecutar una actualización directa en la BD para el tenant 'visionarias': `UPDATE tenants SET config_json = jsonb_set(config_json, '{timezone}', '"America/Lima"') WHERE slug = 'visionarias';`

## 2. Frontend: Nuevos Componentes UI
### Objetivos
- Crear componentes reutilizables que manejen la complejidad de UTC vs Wall Time.
- Eliminar el uso de `<input type="datetime-local" />` que causa el "salto de horario".

### Pasos
1.  **Crear `src/components/ui/timezone-select.tsx`**:
    - Componente tipo Combobox (Shadcn) que lista las zonas horarias internacionales (usando `Intl.supportedValuesOf('timeZone')`).
2.  **Crear `src/components/ui/smart-datetime-picker.tsx`**:
    - **Props**: `value` (ISO string UTC), `onChange` (ISO string UTC), `timezone` (str).
    - **Lógica**:
        - **Render**: Convierte el ISO UTC a "Hora Pared" (Wall Time) en la zona horaria seleccionada para mostrarlo en el input/calendario.
        - **Update**: Toma la "Hora Pared" seleccionada por el usuario + la Zona Horaria -> Convierte a UTC -> Llama a `onChange`.
    - **UI**: Popover con `Calendar` (fecha) + Selectores de Hora/Minuto.
    - **Formato**: Forzar visualización `dd/MM/yyyy`.
