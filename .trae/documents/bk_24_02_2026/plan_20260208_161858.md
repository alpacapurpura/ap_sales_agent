# Plan de Implementación: Módulo "AI Knowledge & Assets"

Este plan detalla la creación de un nuevo módulo en el `Offer Studio` para dotar al agente de capacidades multimedia y conocimiento profundo, siguiendo la arquitectura "Split View" (2 columnas) solicitada.

## 1. Actualización del Esquema de Datos (`schema.ts`)
Necesitamos extender el `OfferSchema` para almacenar estructuradamente los nuevos activos.
- **Multimedia Assets**: Lista de objetos con `url`, `type` (img/video/audio), y `usage_context` (trigger/recomendación).
- **Knowledge Base**: Lista de documentos con `url`, `name`, y `category` para el RAG.

## 2. Implementación de UX/UI (Opción Recomendada: "The AI Brain Step")
Crearemos un paso dedicado llamado **"AI Brain"** o **"Contexto del Agente"**.

### Estructura del Componente (`ai-assets-step.tsx`)
Utilizaremos un layout de **Grid de 2 Columnas** (`grid-cols-12`):
- **Columna Izquierda (Input - span-7)**:
  - **Sección A: Multimedia Kit**.
    - *Upload Zone*: Arrastrar archivos.
    - *Context Cards*: Cada archivo subido tendrá un campo "Trigger/Contexto" (ej: "Enviar cuando pregunten precio").
  - **Sección B: Knowledge Base (RAG)**.
    - *Upload Zone*: Específico para PDFs/TXTs.
    - *Tagging*: Categorizar (Técnico, Ventas, Legal).

- **Columna Derecha (Info/Educativa - span-5)**:
  - **Panel "Why it Matters"**: Explicación dinámica.
    - *Para Multimedia*: "El agente usa esto para generar confianza visual."
    - *Para RAG*: "Estos documentos reducen las alucinaciones en preguntas técnicas."
  - **Best Practices**: Tips visibles (ej: "Usa PDFs con texto seleccionable, no escaneos").

## 3. Integración en el Wizard
- Modificar el orquestador del wizard para insertar este paso en una posición lógica (probablemente antes de `Rules` y después de `Value Stack`).

## 4. Conexión con Backend (Preparación)
- Asegurar que el frontend envíe estos metadatos correctamente para que el servicio `vector_store.py` (ya existente) pueda eventualmente ingerirlos usando la lógica de "Tenant Isolation" y "Semantic Storage".

---
*Nota: Este plan asume el uso de componentes existentes de Shadcn (Card, Input, Badge) y no requiere nuevas librerías, solo la lógica de composición.*
