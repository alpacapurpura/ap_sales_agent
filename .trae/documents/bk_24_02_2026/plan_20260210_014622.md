# Confirmación y Justificación de la Arquitectura

**¿Es esta la arquitectura correcta?**
**Sí, absolutamente.**
Para un sistema "Agentic" como el tuyo, la extracción "Schema-Driven" es el estándar moderno (SOTA) por tres razones:
1.  **Polimorfismo Real**: Hoy extraes "Resumen de Web" para Onboarding, pero mañana el Agente de Ventas necesitará extraer "Tabla de Precios" o "Lista de Socios". Con esta arquitectura, **no cambias el código**, solo pasas un nuevo esquema Pydantic.
2.  **Limpieza Cognitiva**: Al separar la "Navegación" (Requests/Firecrawl) de la "Comprensión" (LLM + Schema), permites que el grafo de scraping maneje la suciedad del HTML, entregando datos limpios a tus agentes principales.
3.  **Preparado para el Futuro**: Si `requests` deja de funcionar (bloqueos), puedes cambiar el nodo `fetch_html` por `Selenium` o `Firecrawl` en un solo lugar, y todos los agentes (Ventas, Onboarding) se benefician de la mejora automáticamente sin tocar su lógica.

# Plan de Implementación: Módulo `web_extractor`

## 1. Stack y Dependencias
- **Librería**: `langgraph` + `langchain-core`.
- **Dependencia Nueva**: `beautifulsoup4` (en `backend/requirements.txt`).
    - *Rol*: Limpieza eficiente de HTML (eliminar scripts/estilos) para reducir consumo de tokens antes de la extracción.

## 2. Diseño del Subgrafo (`backend/src/core/agents/web_extractor/`)

### A. Estado (`state.py`)
```python
class WebExtractorState(TypedDict):
    url: str
    target_schema: Dict[str, Any]  # JSON Schema flexible
    raw_content: str               # HTML limpio
    extracted_data: Dict[str, Any] # Resultado final
    error: Optional[str]
```

### B. Nodos (`nodes.py`)
1.  **`fetch_html`**:
    - Usa `requests` con User-Agent rotativo simple.
    - Limpia con `BeautifulSoup` (Body text).
    - *Fallback*: Estructura lista para conectar Firecrawl si falla.
2.  **`extract_structured`**:
    - LLM (`gpt-4o-mini` recomendado por velocidad/costo).
    - `model.with_structured_output(schema)` para garantizar que la salida cumpla el contrato.

### C. Grafo (`graph.py`)
- Definición del `StateGraph` compilado que orquesta: `fetch` -> `extract`.

## 3. Integration Layer (Adapter)
Crearemos `src/core/services/web_extractor_adapter.py` para exponer el grafo como una función Python nativa, ocultando la complejidad de LangGraph a los otros servicios:
```python
# Uso futuro en cualquier parte del código:
data = await extract_from_url(url="...", schema=CompanyInfoSchema)
```
