# Plan de Implementación: Gestión de Citas Personalizadas

## 1. Backend: Infraestructura de Links y Leads
### 1.1 Modelo de Datos (Nuevo)
*   Crear tabla `booking_links` en PostgreSQL para trazabilidad.
    *   Campos: `id`, `tenant_id`, `lead_id`, `event_slug`, `token`, `expires_at`, `status` (ACTIVE, USED).
*   Actualizar modelos SQLAlchemy (`BookingLink`) y esquemas Pydantic.

### 1.2 Nuevos Endpoints (API)
*   `GET /api/v1/leads/search`: Búsqueda de leads por nombre (autocompletado).
*   `POST /api/v1/calendar/links`: Generación de links personalizados.
    *   Valida existencia del Lead.
    *   Genera token único.
    *   Guarda en DB con fecha de expiración.
*   `GET /api/v1/calendar/links/{token}`: Validación y recuperación de contexto (Lead Info) para el frontend.

### 1.3 Modificación del Flujo de Reserva
*   Actualizar endpoint de reserva (`/book`) para aceptar `booking_token` opcional.
*   Si se envía token:
    *   Validar validez y expiración.
    *   Asociar la cita (`Appointment`) forzosamente al `lead_id` del link.
    *   Marcar el link como usado (opcional, para trazabilidad).

## 2. Frontend: Interfaz de Gestión (Dashboard)
### 2.1 Renombrado y Reestructuración (`EventTypeView`)
*   Cambiar textos "Tipos de Cita" -> "Citas Genéricas".
*   Rediseñar Card de Cita:
    *   Agrupar "Compartir" y "Copiar" bajo etiqueta "Genérico".
    *   Añadir botón principal "Crear reunión para Lead | Cliente".
    *   Deshabilitar clic en todo el card (solo editar vía menú).

### 2.2 Modal de Generación de Links
*   Implementar buscador de Leads con *debounce* y autocompletado.
*   Selector de expiración (7, 14, 30 días).
*   Vista de resultado: Link generado, botón Copiar y Compartir.

## 3. Frontend: Página de Reserva (Landing)
### 3.1 Detección de Contexto
*   Detectar parámetro `?token=...` en la URL `/book/...`.
*   Consultar API para validar token y obtener datos del Lead.

### 3.2 Adaptación del Formulario
*   Si hay token válido:
    *   Pre-llenar Nombre y Email.
    *   **Bloquear/Ocultar campo Nombre** (Solo lectura).
    *   Mostrar indicador visual: "Reserva personalizada para {Nombre}".
*   Enviar `booking_token` al confirmar la reserva.

## 4. Tareas Técnicas Adicionales
*   Migración de base de datos (Alembic) para la nueva tabla.
*   Tests de integración para el flujo de token.
