# Shopify OAuth Host Mismatch Resolution Spec

## Why
When connecting a Shopify store from the Frontend, the `redirect_uri` (generated by the Backend) and the `application_url` (configured in Shopify as the Backend URL) cause a "Host Mismatch" error. Shopify requires the `redirect_uri` to match the `application_url` host for Embedded Apps, especially when using the Authorization Code Grant flow initiated from the client side.

## What Changes
- **Configuration**:
  - Update `shopify.app.toml` to set `application_url` to the Frontend URL (`https://laptopchris.alpacapurpura.lat`).
  - Update `shopify.app.toml` to add the Frontend callback URL (`https://laptopchris.alpacapurpura.lat/api/auth/shopify/callback`) to `redirect_urls`.
- **Backend (`backend/src/modules/connections/api/shopify.py`)**:
  - Modify `generate_auth_url` to construct the `redirect_uri` pointing to the Frontend callback.
  - Add a new endpoint `POST /api/v1/connections/shopify/auth/exchange` that accepts the code payload from the Frontend proxy and performs the token exchange.
- **Frontend (`frontend/src/app/api/auth/shopify/callback/route.ts`)**:
  - Implement a new API route to handle the Shopify OAuth callback.
  - Proxy the `code`, `shop`, `hmac`, `state` to the Backend's new `exchange` endpoint.
  - Redirect the user to the App Home upon success.

## Impact
- **Affected Specs**: None directly.
- **Affected Code**:
  - `shopify_app/shopify.app.toml`
  - `backend/src/modules/connections/api/shopify.py`
  - `frontend/src/app/api/auth/shopify/callback/route.ts` (New file)

## ADDED Requirements
### Requirement: Frontend OAuth Callback Proxy
The Frontend SHALL implement an API route at `/api/auth/shopify/callback` that:
1. Receives GET requests from Shopify with `code`, `shop`, `hmac`, `state`.
2. Validates the presence of required parameters.
3. Sends a POST request to the Backend endpoint `/api/v1/connections/shopify/auth/exchange` with the received parameters in the body.
4. Handles the Backend response:
   - **Success**: Redirects the user to `/marketing-studio/connections?status=success&channel=shopify`.
   - **Error**: Redirects the user to `/marketing-studio/connections?status=error&message={error_message}`.

### Requirement: Backend Token Exchange Endpoint
The Backend SHALL provide a POST endpoint `/api/v1/connections/shopify/auth/exchange` that:
1. Accepts a JSON payload containing `code`, `shop`, `hmac`, `state`.
2. Verifies the HMAC signature using `ShopifyConnector.verify_hmac`.
3. Validates the `state` (tenant_id).
4. Exchanges the `code` for an access token using `ShopifyConnector.exchange_token`.
5. Verifies and saves the connection (reusing logic from `auth_callback`).
6. Returns a JSON response indicating success or failure.

## MODIFIED Requirements
### Requirement: Auth URL Generation
The `generate_auth_url` endpoint in Backend SHALL construct the `redirect_uri` using the Frontend base URL (`https://laptopchris.alpacapurpura.lat`) instead of the Backend URL.
- **Config**: Use `SHOPIFY_FRONTEND_URL` (or derive from `application_url` logic if updated) for the base.
- **Path**: Append `/api/auth/shopify/callback`.

## REMOVED Requirements
### Requirement: Backend Direct Callback (Optional)
**Reason**: The direct backend callback `/api/v1/connections/shopify/auth/callback` is no longer the primary redirect target for client-initiated flows, but SHOULD be kept for backward compatibility or direct backend-initiated flows if any. However, it will not match the new `application_url` host requirement.
**Migration**: Update all clients to use the new flow. The old endpoint remains as a legacy or fallback if needed, but the primary flow uses the proxy.
