  Two fixes in the meta.py router:

  **Fix 1 - Disconnect endpoint (line 444-452):**
  The current `disconnect` only deactivates the master META connection but leaves child asset connections (facebook_page, instagram_account, meta_ads_account, meta_pixel, whatsapp_business_account) active and dangling. This creates orphaned rows that cause state inconsistency on reconnect.

  Update the `disconnect` endpoint to also deactivate all child asset connections:
  ```python
  @router.delete("/disconnect")
  async def disconnect(
      user: User = Depends(get_current_user),
      repo: ChannelConnectionRepository = Depends(_get_repo),
  ):
      connection = repo.get_by_tenant_and_type(user.tenant_id, ChannelType.META)
      if connection:
          # Deactivate all child asset connections first
          child_assets = repo.get_all_by_tenant_and_types(user.tenant_id, _ASSET_CHANNEL_TYPES)
          for asset in child_assets:
              repo.deactivate(asset)
          # Then deactivate master
          repo.deactivate(connection)
      return {"status": "disconnected"}
  ```

  <action>
  The frontend `handleDisconnect` (line 368-382) sets `setStatus({ is_connected: false })` which drops the `is_configured` field. When the NotConnectedScreen renders, `isConfigured` becomes `status?.is_configured ?? false` which is `false` -- this disables the Connect button with `disabled={isConnecting || !isConfigured}`.

  **Fix 1 - handleDisconnect state:**
  Preserve `is_configured` when setting disconnect state:
  ```typescript
  setStatus((prev) => ({ is_connected: false, is_configured: prev?.is_configured }));
  ```
  Instead of:
  ```typescript
  setStatus({ is_connected: false });
  ```

  **Fix 2 - Force refresh on tab=meta query param:**
  When the callback page redirects to `/${tenantId}/settings?tab=meta`, the MetaView may not properly re-fetch if it was previously mounted (React component state might persist across Next.js client navigations within the same layout).

  Add the `tab` search param to the loadAll dependency to force a refresh when arriving from the callback redirect. In the MetaView component, add:
  ```typescript
  const searchParams = useSearchParams();
  const tabParam = searchParams?.get("tab");
  ```
  Import `useSearchParams` from `next/navigation` (already imported for useParams).

  Then update the useEffect that calls loadAll to include tabParam as a dependency:
  ```typescript
  useEffect(() => {
    loadAll();
  }, [loadAll, tabParam]);
  ```
  This ensures that when the user is redirected back from OAuth with `?tab=meta`, the component re-fetches fresh status from the backend.

  **Fix 3 - Add useSearchParams import:**
