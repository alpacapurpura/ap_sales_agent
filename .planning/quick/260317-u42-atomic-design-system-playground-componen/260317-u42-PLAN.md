**Step 1: Create types (types.ts)**

Define the registry schema:
```typescript
export type AtomicLevel = 'token' | 'atom' | 'molecule' | 'organism';

export interface ComponentEntry {
  name: string;              // e.g. "Button"
  atomicLevel: AtomicLevel;
  filePath: string;          // relative from frontend/src
  source: 'shadcn' | 'shared' | 'feature';
  featureSlice?: string;     // e.g. "sales", "brand" — only for feature-scoped
  variants?: string[];       // CVA variant names if applicable
  props?: string[];          // key prop names
  description: string;       // one-line purpose
  issues?: string[];         // problems found during audit
}

export interface DesignToken {
  category: 'color' | 'typography' | 'spacing' | 'radius' | 'shadow';
  name: string;
  cssVar?: string;
  tailwindClass: string;
  value: string;
}
```

**Step 2: Audit and build registry (registry.ts)**

Systematically scan ALL frontend component directories:
1. `components/ui/` — 37 Shadcn primitives. Classify each: most are atoms (Button, Input, Badge, Label, Checkbox, etc.), some are molecules (Form, Command, Dialog, Sheet, DropdownMenu, AlertDialog), some are organisms (DataTable if present, Calendar).
2. `components/shared/` — Classify: error-boundary (atom), development-tools (atom), mode-toggle (atom), layout/ (organism).
3. `features/*/components/` — Scan ALL 10 feature directories. For each component file found, classify by atomic level. Flag duplicates (components that exist in multiple features doing similar things).

For each component, read the actual file to determine: exported props interface, CVA variants (look for `cva()` calls), composition complexity. Record any issues found (missing types, inconsistent patterns, no CVA where expected, duplicated functionality).

Export `COMPONENT_REGISTRY: ComponentEntry[]` and `DESIGN_TOKENS: DesignToken[]`.

For tokens, extract from `tailwind.config.ts` and `globals.css`: brand colors, font sizes, spacing scale, border radii, shadows.

**Step 3: Write AUDIT.md**

Create diagnostic document with sections:
- **Summary Stats**: Total components, per-level counts, per-source counts
- **Inconsistencies Found**: Components not following CVA pattern, inconsistent prop naming, mixed import styles
- **Duplications**: Components in features that duplicate Shadcn or shared components
- **Missing from Shadcn**: Standard UI patterns hand-rolled instead of using Shadcn
- **Atomic Level Violations**: Components at wrong abstraction level (e.g., an "atom" that composes multiple other components)
- **Recommendations**: Prioritized list of refactoring actions for follow-up task

Be honest — the user said "todo esta bien feito". Document the real state.
