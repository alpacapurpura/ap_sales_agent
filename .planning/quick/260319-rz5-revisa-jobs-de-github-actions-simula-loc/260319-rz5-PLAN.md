# Quick Plan: Simulate CI Jobs Locally, Fix Errors, Deploy to Production

## Objective

Run each of the 5 CI/CD pipeline jobs locally (quality-gates, security-scan, build, deploy, healthcheck) to validate the current uncommitted changes pass. Fix any errors found, then push to main to trigger the real pipeline.

**Important:** There are uncommitted changes on main (brand studio logo/visuals refactor + new logos section + migration 013). All of these must pass CI before pushing.

## Task 1: Simulate quality-gates job locally (lint + test for both services)

Build and run the exact same Docker targets the CI uses. Fix any failures before proceeding.

**Steps (run inside project root, NOT inside containers):**

1. **Backend lint** — Build the `lint` target and run it:
   ```bash
   docker build -f backend/Dockerfile --target lint -t visionarias/backend-lint:local ./backend
   docker run --rm visionarias/backend-lint:local
   ```
   - Expected: `ruff check src` exits 0 with no errors
   - If fails: fix lint errors with `ruff check src --fix` inside dev container, re-run

2. **Backend tests** — Build the `test` target and run it:
   ```bash
   docker build -f backend/Dockerfile --target test -t visionarias/backend-test:local ./backend
   docker run --rm visionarias/backend-test:local
   ```
   - Expected: `pytest` exits 0, all tests pass
   - If fails: diagnose and fix test failures, re-run
   - Note: test target copies `.env.test` to `.env` — no external DB needed for unit tests

3. **Frontend lint** — Build the `test` target and run lint:
   ```bash
   docker build -f frontend/Dockerfile --target test -t visionarias/frontend-test:local ./frontend
   docker run --rm visionarias/frontend-test:local npm run lint
   ```
   - Expected: ESLint exits 0 with no errors
   - If fails: fix lint errors in frontend source, re-build and re-run

4. **Frontend tests** — Run the test target default CMD:
   ```bash
   docker run --rm visionarias/frontend-test:local
   ```
   - Expected: `npm run test` (vitest) exits 0, all tests pass
   - If fails: diagnose and fix test failures, re-run

**Verify:** All 4 commands exit with code 0.
**Done:** Backend lint, backend tests, frontend lint, and frontend tests all pass locally using the same Docker targets as CI.

## Task 2: Simulate security-scan and build jobs locally

1. **Backend final image** — Build the production target:
   ```bash
   docker build -f backend/Dockerfile --target final -t visionarias/backend-scan:local ./backend
   ```
   - Expected: builds successfully (no runtime errors, no missing deps)

2. **Frontend runner image** — Build with placeholder build-args (matching CI security-scan job):
   ```bash
   docker build -f frontend/Dockerfile --target runner -t visionarias/frontend-scan:local ./frontend \
     --build-arg NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=ci-placeholder-key \
     --build-arg NEXT_PUBLIC_API_URL=http://localhost:8000 \
     --build-arg NEXT_PUBLIC_APP_URL=http://localhost:3000 \
     --build-arg INTERNAL_API_URL=http://localhost:8000
   ```
   - Expected: `npm run build` succeeds, runner image created
   - If fails: fix TypeScript/build errors, re-run

3. **Trivy scan** (optional, only if `trivy` is available locally):
   ```bash
   trivy image --severity HIGH,CRITICAL --ignore-unfixed visionarias/backend-scan:local
   trivy image --severity HIGH,CRITICAL --ignore-unfixed visionarias/frontend-scan:local
   ```
   - If trivy not installed, skip — CI will run it. The critical part is that images BUILD successfully.

**Verify:** Both `docker build` commands exit 0 and produce tagged images (`docker images | grep visionarias`).
**Done:** Production Docker images for both backend and frontend build successfully with current code.
