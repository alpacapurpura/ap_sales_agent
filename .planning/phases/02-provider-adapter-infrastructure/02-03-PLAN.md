    5. Create `backend/src/modules/analytics/workers/scheduler.py`:
       - `async def run_tick_scheduler(ctx)`: The tick function that runs every minute
         - Gets all active tenants from DB ordered by extraction_priority DESC (via ctx["db_factory"])
         - For each tenant, checks if current UTC time matches 3am in tenant's timezone
         - If match, enqueues `run_tenant_extraction` job via ARQ
         - Uses `zoneinfo.ZoneInfo` (stdlib) for timezone conversion per research recommendation
         - Default timezone: uses tenant.timezone field (defaults to "UTC" per TenantModel)
         - Orders by tenant.extraction_priority DESC so premium tenants are enqueued first
         - Log: "Scheduler tick: checked N tenants, enqueued M extractions"

    6. Create `backend/src/modules/analytics/workers/tasks.py`:
       - `async def run_tenant_extraction(ctx, tenant_id: str, provider: str)`:
         - Import ETLService lazily inside function body (late binding to avoid import-time issues when Plan 02 hasn't been executed yet)
         - Creates DB session from ctx["db_factory"]
         - Instantiates ConnectionPortImpl and MetricsCache
         - Creates ETLService
         - Calls etl_service.run_extraction(UUID(tenant_id), provider)
         - On ConnectionRevokedException: log error, don't retry (raise without Retry)
         - On RateLimitExceeded or other transient errors: Fibonacci backoff using ARQ Retry
         - Fibonacci sequence: [1, 1, 2, 3, 5, 8, 13] minutes
         - `defer = fib[min(ctx["job_try"] - 1, len(fib) - 1)] * 60` seconds
         - `raise Retry(defer=defer)`
       - `async def run_initial_load(ctx, tenant_id: str, provider: str)`:
         - Triggered when user connects a new provider (not waiting for next cron)
         - Same as run_tenant_extraction but with start_date = 7 days ago (initial load window per user decision)
         - Parameterizable: initial_days=7 default, can be expanded in future milestones
