<task type="auto" tdd="true">
  <name>Task 1: Batch inactivity detection with score decay</name>
  <files>
    backend/src/modules/crm/application/services/inactivity_service.py,
    backend/src/modules/analytics/workers/tasks.py,
    backend/src/modules/analytics/workers/settings.py,

  <behavior>
    - InactivityService.run_batch(tenant_id=None) processes all tenants if tenant_id is None
    - Profiles with last_activity_at older than 14 days (configurable) are flagged is_inactive=true
    - Profiles with recent activity have is_inactive=false (recovery)
    - Score decay: each inactive profile's lead_score *= (1 - 0.05)^days_since_last_activity
    - Decay clamped to floor 0.0
    - CUSTOMER stage profiles: decay is PAUSED (score unchanged) but is_inactive flag still set
    - Score decay below threshold triggers backward stage transition with triggered_by="decay"
    - Batch processes in chunks of 500 to avoid stale data (per research pitfall 6)
    - Uses UPDATE ... WHERE for atomic conditional updates where possible
    - last_activity_at updated on every journey_event write (or computed from max(journey_events.occurred_at))
    - ARQ task run_inactivity_detection wraps InactivityService.run_batch
    - Scheduled daily via ARQ cron (e.g., 4am UTC — alongside or after ETL scheduler)
  </behavior>
  <action>
    1. **Create InactivityService** (`backend/src/modules/crm/application/services/inactivity_service.py`):
       - `__init__(self, db: Session)`
       - `run_batch(self, tenant_id: Optional[UUID] = None) -> dict`:
         - Query profiles where last_activity_at < threshold_date OR last_activity_at IS NULL
         - Process in batches of 500 (LIMIT/OFFSET or keyset pagination)
         - For each batch:
           - Flag is_inactive=True for profiles past threshold
           - Flag is_inactive=False for profiles that have become active again (last_activity_at >= threshold)
           - Apply score decay for inactive profiles:
             - Calculate days_inactive = (now - last_activity_at).days
             - new_score = lead_score * (1 - DECAY_CONFIG.daily_decay_rate) ^ days_inactive
             - Clamp to max(new_score, DECAY_CONFIG.min_score)
             - SKIP decay for CUSTOMER stage (per locked decision)
           - Check if decayed score crosses a threshold downward -> backward transition
             - Use _determine_stage() logic (same as LifecycleService)
             - Create lifecycle_transition with triggered_by="decay", metadata={previous_score, new_score, days_inactive, decay_rate}
           - Commit per batch
         - Return {profiles_flagged_inactive: N, profiles_recovered: M, scores_decayed: K, transitions: T}
       - `update_last_activity(self, profile_id: UUID, tenant_id: UUID, activity_at: datetime)`:
         - Atomic UPDATE customer_profiles SET last_activity_at = activity_at WHERE id = profile_id AND tenant_id = tenant_id
         - Called when a journey_event is written (wire this in the journey event creation flow)

    2. **Add ARQ task** to `backend/src/modules/analytics/workers/tasks.py`:
       ```python
       async def run_inactivity_detection(ctx: dict) -> dict:
           """Batch job: flag inactive profiles and apply score decay."""
           from src.modules.crm.application.services.inactivity_service import InactivityService
           db = ctx["db_factory"]()
           try:
               service = InactivityService(db)
               result = service.run_batch()
               return result
           finally:
               db.close()
       ```
       Use late-binding imports (same pattern as existing ETL tasks per Phase 2 decision).

    3. **Register in ARQ settings** (`backend/src/modules/analytics/workers/settings.py`):
       - Add `run_inactivity_detection` to WorkerSettings.functions list
       - Add a daily cron job to SchedulerSettings.cron_jobs: `cron(run_inactivity_detection, hour=4, minute=0)` (4am UTC daily)
       - Import with late binding to avoid circular imports

    4. **Write tests** (`tests/modules/crm/test_inactivity_detection.py`):
       - test_flags_inactive_after_threshold — profile with last_activity 15 days ago -> is_inactive=True
       - test_does_not_flag_active_profile — profile with last_activity 5 days ago -> is_inactive=False
       - test_recovers_previously_inactive — inactive profile with new activity -> is_inactive=False
       - test_score_decay_applied — inactive 7 days, original score 40 -> score ~27.8 (40 * 0.95^7)
       - test_decay_clamps_to_floor — very old inactive profile -> score = 0.0
       - test_customer_decay_paused — CUSTOMER profile inactive but score unchanged
       - test_customer_still_flagged_inactive — CUSTOMER profile gets is_inactive=True despite no decay
       - test_decay_triggers_backward_transition — MQL(42) decays to 35 -> LEAD, audit record created
       - test_batch_processes_in_chunks — verify batch processing works with >500 profiles (mock or check query patterns)
       - test_null_last_activity_treated_as_inactive — profile with last_activity_at=NULL -> is_inactive=True
  </action>

  </verify>
  <done>
    Batch inactivity detection flags profiles after 14 days, applies 5%/day score decay (paused for CUSTOMER), triggers backward transitions when score drops below thresholds, and runs daily via ARQ cron at 4am UTC.

         - Load profile with FOR UPDATE
