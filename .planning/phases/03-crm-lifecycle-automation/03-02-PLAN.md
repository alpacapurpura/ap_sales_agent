<task type="auto" tdd="true">
  <name>Task 1: LifecycleService — scoring engine with threshold transitions and audit trail</name>
  <files>
    backend/src/modules/crm/application/services/lifecycle_service.py,

  <behavior>
    - recalculate_score(profile_id, tenant_id): sums weights from all journey_events, adds fit score from profile traits, clamps to floor 0
    - recalculate_score skips scoring for CUSTOMER stage (returns current score unchanged)
    - recalculate_score uses SELECT ... FOR UPDATE to prevent race conditions
    - _determine_stage(score): returns SQL if >=70, MQL if >=40, LEAD if >=10, else SUBSCRIBER
    - Stage transition creates lifecycle_transitions record with triggered_by="scoring_rule"
    - Forward transition: SUBSCRIBER(score=5) + events pushing to 45 -> MQL
    - Backward transition: MQL(score=42) with decay dropping to 35 -> LEAD
    - Stage skipping: SUBSCRIBER(score=5) + high-intent events pushing to 75 -> SQL directly
    - CUSTOMER profile: score recalculation returns early, no transition
    - handle_sale_completed(event): CONVERSION -> sets CUSTOMER + first_conversion_at; EXPANSION -> increments lifetime_value
    - handle_sale_completed on CHURNED profile: reactivation -> CUSTOMER with triggered_by="reactivation"
    - PipelineService.move_stage delegates to LifecycleService
  </behavior>
  <action>
    1. **Create LifecycleService** (`backend/src/modules/crm/application/services/lifecycle_service.py`):
       - `__init__(self, db: Session)` — instantiates LifecycleRepository and uses db directly
       - `recalculate_score(self, profile_id: UUID, tenant_id: UUID) -> float`:
         - SELECT profile FOR UPDATE
         - If lifecycle_stage == CUSTOMER, return profile.lead_score unchanged
         - Query all journey_events for profile
         - Sum weights: merge engagement + intent dicts from SCORING_WEIGHTS, lookup each event.event_name
         - Add fit score via _calculate_fit_score(profile) — check computed_traits for fit flags, apply once
         - Clamp to max(score, 0.0)
         - Update profile.lead_score
         - Call _check_threshold_transition(profile, score)
         - Commit and return score
       - `_calculate_fit_score(self, profile) -> float`:
         - Check profile.traits or computed_traits for FinancialCapacity, SophisticationLevel, BusinessStage
         - Map enum values to SCORING_WEIGHTS.fit keys
         - Return sum of applicable fit weights
         - Store "fit_score_applied" flag in computed_traits to avoid re-adding
       - `_determine_stage(self, score: float) -> LifecycleStage`:
         - Return SQL/MQL/LEAD/SUBSCRIBER based on thresholds
       - `_check_threshold_transition(self, profile, score)`:
         - Determine new stage from score
         - If different from current lifecycle_stage, call _transition()
       - `_transition(self, profile, new_stage, reason, triggered_by, metadata=None)`:
         - Record old stage
         - Set profile.lifecycle_stage = new_stage
         - Create LifecycleTransition via repository (from_stage, to_stage, reason, triggered_by, score_at_transition=profile.lead_score, metadata)
       - `handle_sale_completed(self, event: DomainEvent)`:
         - Extract customer_id, stage, amount from event.payload
         - Load profile (with FOR UPDATE)
         - If stage == CONVERSION:
           - _transition(profile, CUSTOMER, reason="CONVERSION sale completed", triggered_by="sale_event", metadata={sale_id, amount, offer_id})
           - Set profile.first_conversion_at = datetime.now(UTC) if not already set
           - Set profile.lifetime_value += amount
         - If stage == EXPANSION:
           - profile.lifetime_value += amount (keep CUSTOMER stage)
           - Create transition record with triggered_by="sale_event" for audit
         - If current stage is CHURNED (reactivation):
           - _transition(profile, CUSTOMER, reason="Reactivation via sale", triggered_by="reactivation", metadata={sale_id, previous_stage="churned"})
         - Commit
       - `force_stage(self, profile_id, tenant_id, new_stage, admin_user_id, note="")`:
         - Manual override API support
         - _transition with triggered_by="manual", metadata={admin_user_id, note}

    2. **Update PipelineService.move_stage** in `lead_service.py`:
       - Replace `pass` with delegation to LifecycleService.force_stage (for manual stage changes via API)
       - Or deprecate PipelineService if the API should use LifecycleService directly (check api/pipeline.py usage)

    3. **Write tests** (`tests/modules/crm/test_lifecycle_scoring.py`):

       - test_threshold_transition_lead_to_mql — score crosses 40
       - test_threshold_transition_mql_to_sql — score crosses 70
       - test_stage_skipping — score jumps from 5 to 75, goes directly to SQL
       - test_backward_transition — score drops below threshold, stage moves back
       - test_customer_stage_exempt — CUSTOMER profile score not recalculated
       - test_transition_creates_audit_record — verify lifecycle_transitions row created
       - test_fit_score_applied_once — fit score only added on first calculation
       Use conftest fixtures from plan 01. Mock or use real DB session as appropriate.
