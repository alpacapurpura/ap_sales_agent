## Layout System

### Dashboard Structure

```
MetricsDashboard
├── StageSummaryRow (horizontal scroll, snap-scroll)
│   └── StageCard × 8 (min-width 120px, gap-3)
├── Card (detail container)
│   ├── CardHeader (pb-3)
│   │   └── CardTitle (text-lg)
│   └── CardContent
│       └── [DetailPanel] (one of 8 stages)
```

**Grid/Flex Rules:**
- StageSummaryRow: `flex gap-3 overflow-x-auto pb-2 snap-x snap-mandatory`
- Detail panels: `space-y-4` (vertically stacked sections)
- Header KPIs: 3-column grid (lg:grid-cols-3, md:grid-cols-3, sm:flex flex-col gap-4)
- ChannelGroup: flex flex-col gap-4 (group container)
- ChannelRow: flex items-center justify-between gap-4 (metric row)

**Responsive Breakpoints:**
- Mobile: single-column layout, MetricsDashboard space-y-4
- Tablet (md): 2-column header KPIs, wrapped ChannelGroup
- Desktop (lg): 3-column header KPIs, full-width panels
- Landscape mobile: horizontal scroll for stage cards maintained

**Pre-populated from:** Existing StageSummaryRow, SalesDetail, AdoptionDetail panels define responsive behavior via Tailwind's md:/lg: prefixes.

## Micro-Interactions

### Animations & Transitions

| Interaction | Trigger | Animation | Duration | Easing |
|-------------|---------|-----------|----------|--------|
| **Stage card hover** | mouseenter | scale(1.02) + shadow elevation | 150ms | ease-out |
| **Stage card selection** | click | ring expand, border-primary glow | 200ms | ease-in-out |
| **Skeleton shimmer** | load state | gradient sweep left-to-right | 1.5s | linear, infinite |
| **KPI count-up** | data arrival | number animate from 0 → value | 600ms | ease-out |
| **Panel fade-in** | activeStage change | opacity 0 → 1 | 200ms | ease-in |
| **ChannelRow hover** | mouseenter | bg-primary/5 + subtle lift | 100ms | ease-out |
| **Sidebar slide-in** | metric click | translateX -100% → 0% | 250ms | ease-in-out |
| **Bottleneck banner pulse** | render (critical) | 1px border-red glow pulse every 2s | infinite | ease-in-out |

**Easing Reference:** Tailwind defaults (ease-in, ease-out, ease-in-out).

**Pre-populated from:** Existing StageCard uses `transition-all`; phase requirements mandate "subtle animations — scale+shadow on hover, count-up numbers on load, fade-in panel transitions, subtle highlight on ChannelRow hover, skeleton shimmer".

## Dashboard Research Findings

### Reference Dashboards Analyzed

1. **Amplitude Analytics** — Funnel visualization with 60/30/10 color split, metric cards with count-up animation, drill-down sidebar with sparklines
2. **Intercom Insights** — Horizontal stage progression, real-time metric shimmer, proportional bar graphs, color-coded severity badges
3. **Datadog Monitoring** — Side panel details on metric click, multi-metric sparklines, custom time range picker (deferred), responsive grid
4. **Mixpanel Funnels** — Stage cards with conversion rates, hover tooltips, chevron indicators for drill-down, muted fallback states
5. **HubSpot Pipeline** — Column-based stage layout, deal cards with metadata, right-side detail panel, drag-and-drop (not needed)

### Design Principles Applied

- **Visual Hierarchy:** KPI value (largest, boldest) > label (smaller, muted) > secondary metric (smallest, accent color)
- **Progressive Disclosure:** Summary KPI on card, detail on click, granular metrics in sidebar
- **Error Resilience:** Fallback mocks with "datos simulados" badge, retry buttons on failure, cached data fallback
- **Responsive-First:** Mobile stack (single column), tablet (2-col KPIs), desktop (3-col KPIs + full width panels)
- **Subtle Animation:** Micro-interactions for feedback, no distraction, 150-250ms durations
- **Accessibility:** All interactive elements keyboard accessible, ARIA labels on custom components, color not sole information carrier

## Notes for Planner/Executor

- **API calls in StageCard:** Each card will make a parallel call to its stage endpoint (8 calls total). Consider loading states and error fallbacks.
- **Conversion rate formula:** Already defined in CONTEXT.md as "Stage N-1 count / Stage N count" — compute on backend and pass in miniFunnel.conversionRate.
- **Sidebar granularity:** Per-metric detail means campaign-level data for retargeting, offer-level data for sales, evangelist list for evangelization, etc. Planner must map which data structure feeds each sidebar type.
- **Responsive sidebar:** On mobile, sidebar uses full-height overlay Sheet. On desktop, Sheet can be wider (400px). Verify shadcn Sheet responsive behavior.
- **Icon library:** Executor should use react-icons (lucide-react) or find a small SVG icon library for platform brands. Avoid loading all icons at once (tree-shake).
- **Dark mode:** All new components must respect dark mode via Tailwind's `dark:` prefix and existing CSS variables. Test in both modes.
