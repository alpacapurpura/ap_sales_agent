  <action>
    Refactor `MetricsService.get_attraction_metrics()` to build multi-metric DTOs:

    1. **Change aggregation query**: Instead of fetching a single value per channel_slug, fetch all metric rows for each channel. The OfficialMetricsRepository.get_channel_summary() should return rows with (channel_slug, metric_name, value). If the current query groups by channel_slug only, update it to also include metric_name in the result (or query without grouping and build the metric list in Python).

    2. **Build MetricValueDTO lists**: For each connected channel, look up all official_metrics rows matching that channel_slug. For each row, create a MetricValueDTO with name=row.metric_name, value=row.value, unit=row.unit, currency=row.currency. If the metric has extra data (engagement breakdown), populate the breakdown field from the ExtractedMetric.extra stored in the official table.

    3. **Group into 4 sections** per CONTEXT.md:
       - `organic_social`: channels with channel_type in ("social") -- ig-organic, yt-organic, fb-organic, tiktok-organic
       - `ga4_search`: channels with channel_type in ("search", "direct") -- google-organic, direct, ai-search-organic
       - `paid`: channels with channel_type == "paid" -- meta-ads, google-ads, tiktok-ads, yt-ads
       - `outbound`: channels with channel_type == "outbound" -- cold-contact

    4. **Compute group totals**: TrafficGroupDTO.totals = dict aggregating metric values by metric_name across all channels in the group. For organic_social: {"reach": sum_reach, "engagement": sum_engagement}. For paid: {"reach": sum, "clicks": sum, "conversions": sum, "spend": sum}.

    5. **Stale detection**: For each channel, check ExtractionRunRepository for the latest run. If the latest run's status is FAILED or RETRYING, set stale=True and error_message based on the failure reason (map to user-facing messages per RESEARCH.md Error UX Casuistry table).

    6. **last_updated header**: Compute as max(computed_at) across all connected channels' official metrics.

    7. **API route**: No structural change needed to `metrics.py` -- it already calls `service.get_attraction_metrics()` and returns the result. The new DTO shape serializes correctly via Pydantic.

    8. **Add re-extraction endpoint**: Add `POST /api/analytics/metrics/attraction/refresh/{channel_slug}` to `metrics.py` that triggers ETLService.run_extraction for just that provider. Apply 15-min cooldown check (read last ExtractionRun for this provider+tenant, reject if < 15 min ago with 429 status).
