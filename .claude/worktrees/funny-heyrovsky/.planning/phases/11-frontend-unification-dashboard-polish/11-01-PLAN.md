## Key References from UI-SPEC.md

**Component Architecture (from UI-SPEC.md Implementation Guidance):**
- DetailSkeleton: Reusable shimmer skeleton wrapper with headerKpis + bar + rows
- DetailEmpty: Empty state wrapper with "Sin datos para este período" copy + contextual CTA
- DetailError: Error state banner with retry button + last cached data fallback
- MetricSidebar: Right-side Sheet for metric drill-down with campaign/offer-level detail
- SidebarContent: Polymorphic content adapter per metric type

**Stage Card Real KPIs (from CONTEXT.md):**
- ATRACCION → total visitors (sum across channels)
- CAPTURA → totalLeads
- NUTRICION → totalMqls
- OPORTUNIDAD → totalSqls
- VENTAS → totalRevenue ($)
- ADOPCION → healthPct (%)
- EXPANSION → netMrr ($)
- EVANGELIZACION → kFactor

**Secondary KPI (Conversion Rate) — CONTEXT.md:**
- Format: "X% conversión"
- Formula: Match mainKpi type; ratio of stage N-1 count to stage N count
- Atraccion exception: No conversion rate (first stage); secondary = total spend across paid channels

**Loading State Pattern (from CONTEXT.md):**
- Skeleton shimmer (animated gray bars) while endpoint loads
- Data appears progressively (no hard block until all 8 endpoints respond)
- Fallback: Show mock values with "datos simulados" badge

**API Endpoints (8 total, all exist from prior phases):**
- `/api/v1/analytics/metrics/attraction`
- `/api/v1/analytics/metrics/capture`
- `/api/v1/analytics/metrics/nurturing`

- `/api/v1/analytics/metrics/adoption`
